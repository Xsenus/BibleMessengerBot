# BibleMessengerBot 1.3.0

Многоязычный Telegram-бот и автоматический загрузчик Библии из **трёх ресурсов**: BibleNLP/eBible, getBible/v2, HelloAO. Продолжение реального проекта 1.2.0, а не новая несвязанная база. Издания записываются в существующую PostgreSQL-схему; настройки чатов, история доставки и прогресс сохраняются.

**В архиве нет скачанных полных Библий и готового дампа.** Здесь исходники, установщик, импортёр, миграции, тесты, документация и Git-история. Тексты скачиваются и проверяются на вашем VPS. «Все» означает все подходящие издания в доступных каталогах трёх адаптеров, прошедшие лицензионный и структурный фильтры; это не все существующие в мире переводы.

## Новая установка

На Ubuntu/Debian с доступом в интернет:

```bash
unzip BibleMessengerBot-1.3.0-ALL-IN-ONE.zip
cd BibleMessengerBot-1.3.0
sudo bash install.sh
```

Установщик запрашивает токен Telegram-бота, создаёт секреты только при новой установке, поднимает PostgreSQL, запускает интеграционные тесты в отдельной временной БД, применяет миграции и выполняет импорт. Новый `.env` использует `BIBLE_PROFILE=all-open` и все три ресурса. После успешной проверки БД запускаются бот, worker и веб-панель. По умолчанию нужны структурно полные 66-книжные ядра на русском и английском; частичные ошибки остальных ресурсов остаются в отчёте и не выдаются за успешную загрузку.

Самому боту не нужны платный API Библии, нейросеть или ключи источников. Внешняя сеть нужна для установки зависимостей и импорта; Telegram-токен нужен для публикаций. Скрипты подготовки `discover`/`download` могут работать без Telegram и PostgreSQL через отдельный Python CLI.

## Наполнение существующей установки

Распакуйте 1.3.0 на **том же Docker-хосте** и перенесите прежний `.env` в новую папку. Сохраните `.env` и резервную копию в защищённом месте. Не создавайте другой пароль для уже существующего тома и не выполняйте `docker compose down -v`.

```bash
# Находясь в новой папке проекта, подставьте фактический путь к прежней:
sudo install -m 600 /path/to/previous/project/.env .env
sudo bash fill_database.sh
```

`fill_database.sh` сначала скачивает и проверяет данные, не останавливая рассылку. Затем делает `pg_dump`, запоминает работающие службы, останавливает их, применяет миграции и импортирует издания отдельными транзакциями. После аудита БД возвращает только ранее работавшие службы. При провале аудита они остаются остановленными. Тот же скрипт можно повторно запускать после обрыва.

```bash
sudo bash fill_database.sh discover
sudo bash fill_database.sh --languages ru,en,es,fr,de
sudo bash fill_database.sh --sources biblenlp,helloao
sudo bash fill_database.sh --editions biblenlp:russyn,helloao:BSB
sudo bash fill_database.sh status --full-report
```

Без фильтров выбирается `all-open`, даже если старый `.env` содержит `extended`. Примеры ID не являются обещанием их доступности: фактический каталог и причины пропусков показывает `discover`. Полное руководство: [MULTISOURCE_IMPORT_RU.md](docs/MULTISOURCE_IMPORT_RU.md).

## Что делает импортёр

Каталоги обнаруживаются автоматически, текст загружается по целому изданию, а не по отдельному стиху. Хранятся исходные файлы, SHA-256, источник, редакция, лицензия, фактические книги/главы/стихи. Есть повторные попытки, ограничение скорости, проверяемая докачка, контроль размера файла и места в кэше, блокировка параллельного запуска, отчёты о частичном результате.

Библия, Новый Завет, Ветхий Завет и неполные издания не смешиваются. Пропуски не заполняются текстом другой редакции. Изменившийся текст не подменяет уже выбранное пользователями издание. Идентификаторы включают ресурс: `biblenlp:russyn`, `helloao:BSB`; точные дубликаты могут ссылаться на одну запись только при совместимой нумерации и атрибуции.

## Языки в Telegram

Язык интерфейса, язык Библии, конкретное издание и расписание хранятся **отдельно для каждого назначения**. `/settings` показывает реальные импортированные варианты. Список языков разбит на страницы, а не ограничен первыми 90.

```text
/language ru @russian_channel
/language en @english_channel
/ui en @english_channel
/translations
/translation helloao:BSB @english_channel
/subscribe sequential 09:00 Europe/Amsterdam @english_channel
```

Бот проверяет права администратора назначения. Для личных сообщений пользователь сам запускает бота. Группы/каналы должны разрешать публикацию боту. Готовы 24 каталога интерфейса, а не интерфейс на всех языках корпуса. Тексты Библии не переводятся машиной. Названия книг используются из конкретного источника, когда они предоставлены; иначе применяется локализованное имя или код USFM.

**Тематические ссылки прежней версии привязаны к нумерации BibleNLP. Для новых источников тематический режим отключён до появления проверенного сопоставления.** Последовательное чтение, планы для достаточно полного корпуса, случайный стих, стих дня и поиск используют само выбранное издание. «Стих дня» не является церковным календарём.

## Проверки и границы

Точный результат текущего прогона: [RELEASE-AUDIT.md](RELEASE-AUDIT.md), JSON и `evidence/`. Сетевые тесты используют синтетические HTTP-ответы, тесты обслуживания — подставной Docker. Это не запуск контейнеров или скачивание реальных полных изданий.

В среде сборки не выполнены настоящий PostgreSQL-импорт, Docker-сборка, Telegram-публикации, полное скачивание и проверка восстановления backup. Установщик содержит проверки для исполнения на VPS. Структурная полнота не заменяет независимую сверку текста и не доказывает наличие полного православного состава.

## Состав
