# BibleMessengerBot

<img src="assets/brand/avatar.png" alt="Открытая Библия и золотой крест" width="96" height="96">

Telegram-бот для чтения Библии и публикаций по расписанию в личных чатах, группах и каналах. Тексты загружаются из BibleNLP/eBible, getBible и HelloAO в PostgreSQL; бот работает с сохранённым корпусом. Для установки не нужны платный библейский API или домен. Нужен собственный Telegram-токен.

**[Открыть работающего бота в Telegram](https://t.me/bibleMessenger_bot)** · [Исходный код](https://github.com/Xsenus/BibleMessengerBot)

**Исходный код не содержит полных библейских текстов, наполненной БД и секретов.** Импорт проверяет лицензионные сведения и структуру каждого издания. Фактический набор доступных текстов зависит от выбранных источников, фильтров и результата загрузки.

## Возможности

- Отдельные настройки языка, издания, времени и часового пояса для каждого чата/канала.
- Приветствие и постоянная клавиатура с основными действиями в личном чате.
- Понятные названия переводов и короткие подписи при чтении; сведения об источнике доступны через `/license`.
- Последовательное чтение, случайный стих, поиск по словам и адресам (`Ин 3:16`, `Пс 22`), планы и темы.
- Кнопка ежедневного стиха и `/daily`: время и часовой пояс видны при включении; `/daily off` отключает рассылку.
- Выделенные номера стихов **[55]** и отправка сохранённых иллюстраций вместе со стихом. Генерация GPT Image 2 medium для случайных/одиночных стихов и расписаний: общий кэш на три календарных месяца, архив версий, общий лимит $10/месяц и по 10 попыток/UTC-сутки для каждого провайдера. [Правила](docs/ILLUSTRATIONS.md).
- Иллюстрации полных глав для «Читать дальше», `/next`, адреса целой главы и последовательной рассылки. Отдельный кэш главы, без повторной оплаты при повторном чтении. [Правила](docs/CHAPTER_ARTWORK.md).
- Постоянное ожидание картинки для всех подтверждённых карточек: один результат обновляет исходные сообщения всех пользователей, без срока 24 часа и дополнительных отправок. [Как это работает](docs/PERSISTENT_ARTWORK.md).
- Пять независимых генераторов с автоматическим переключением: OpenAI, Google Gemini, FLUX, Ideogram, Stability AI. Отсутствующие ключи и сервисы с исчерпанными 10 суточными попытками пропускаются; месячный резерв $10 общий. [Подключение и ошибки](docs/IMAGE_PROVIDERS.md).
- Связные чтения из одного или нескольких стихов с выделением **[16]**; готовая картинка добавляется редактированием исходной карточки. [Подбор отрывков](docs/READINGS.md).
- Кнопки языков под каждым новым библейским сообщением: до шести языков и стрелки, замена текста в том же сообщении с сохранением картинки. [Как пользоваться](docs/MESSAGE_LANGUAGES.md).
- Пул нескольких OpenAI-ключей для картинок с отдельными блокировками, распределением нагрузки и общим бюджетом. [Настройка ключей](docs/IMAGE_PROVIDERS.md#несколько-ключей-openai).
- Озвучка выбранного языка прямо в сообщении: локальные нейросетевые русский/латынь/древнегреческий, голоса других языков, общий кэш и замена дорожки вместе с текстом. Дополнительный платный OpenAI TTS включается отдельно. [Настройка и ограничения](docs/AUDIO.md).
- Утренние и вечерние чтения по отдельному расписанию; `/devotions` включает оба. [Механизм и бюджет](docs/DAILY_ARTWORK.md).
- Зашифрованные копии БД и проверяемые копии картинок в [S3](docs/S3_BACKUP.md).
- 24 каталога интерфейса; список языков Библии строится по реально импортированным данным.
- Проверка прав администратора назначения при командах и нажатиях кнопок.
- Очередь публикаций с сохранением подтверждённых частей и ручным разрешением неоднозначной доставки.
- Три адаптера источников, кэш с SHA-256, повторяемый импорт, сведения об источнике и лицензии.
- Локальная административная страница только для чтения, диагностика, резервное копирование и восстановление.
- Разовая добровольная поддержка проекта через Telegram Stars в личном чате.

Тематические ссылки поддерживаются для нумерации BibleNLP; для других источников этот режим отключён. «Стих дня» — алгоритмический выбор, а не церковный календарь. Подробные [ограничения](docs/LIMITATIONS.md).

## Установка на VPS

Автоматический установщик рассчитан на Ubuntu/Debian с Bash, доступом в интернет и правами `sudo`. На других системах используйте [ручной запуск Docker Compose](docs/INSTALL_RU.md#ручной-запуск-docker-compose). Объём ресурсов зависит от числа изданий; начните с нужных языков и проверяйте фактическое использование диска.

```bash
git clone https://github.com/Xsenus/BibleMessengerBot.git
cd BibleMessengerBot
sudo bash install.sh
```

Установщик создаёт приватный `.env`, сохраняет существующую конфигурацию при повторном запуске, собирает образ, запускает тесты с отдельной временной PostgreSQL-БД, применяет миграции и импортирует тексты. Службы запускаются после проверки БД. По умолчанию `all-open` рассматривает все допустимые издания; это может занять значительное время и место. Для ограниченного первого запуска подготовьте `.env` с фильтрами по [инструкции](docs/INSTALL_RU.md).

PostgreSQL доступен только контейнерам проекта. Административная страница слушает `127.0.0.1:8080` на сервере и открывается через SSH-туннель. Секреты из `.env` нельзя коммитить или прикладывать к issue.

## Первые команды

Откройте своего бота в Telegram и отправьте:

```text
/start
/settings
/language ru
/translations
/subscribe sequential 09:00 Europe/Moscow
/status
```

Для канала добавьте бота администратором с правом публикации. Отправляйте команды боту лично от учётной записи администратора канала:

```text
/settings @your_channel
/language ru @your_channel
/subscribe sequential 09:00 Europe/Moscow @your_channel
```

`/language` выбирает издание заданного языка и поддерживаемый интерфейс; `/ui` меняет только интерфейс. Все команды, роли и планы описаны в [руководстве Telegram](docs/TELEGRAM_SETUP.md).

## Поддержать проект

Библия, поиск, планы и рассылка остаются бесплатными. В личном чате кнопка `⭐ Поддержать` или `/donate` предлагает разовый взнос 25, 50, 100, 250 или 500 Stars; `/donate 100` позволяет задать целую сумму от 1 до 2500. Платёж подтверждается в Telegram, дополнительных прав и автоматических списаний нет.

Условия — `/terms`, история своих операций — `/donations`, обращение по оплате — `/paysupport Текст обращения`. Заявка сохраняется в БД и требует рассмотрения оператором. [Платежи, поддержка и возвраты](docs/DONATIONS.md).

## Импорт и обслуживание

```bash
# Посмотреть каталог без записи в PostgreSQL.
sudo bash fill_database.sh discover --languages ru,en

# Скачать, проверить и добавить издания выбранных языков.
sudo bash fill_database.sh --languages ru,en

# Последний полный отчёт, фактическое состояние БД и резервная копия.
sudo bash fill_database.sh status --full-report
docker compose run --rm --no-deps bootstrap python -m app.cli audit
sudo bash backup.sh
```

`fill_database.sh` сначала готовит тексты при работающих службах, затем делает backup, останавливает службы, импортирует и проверяет БД. Возвращаются только ранее работавшие службы. Код завершения `2` означает частичный результат: отчёт содержит причины. Без явного `--profile` этот скрипт использует `all-open`, даже если `.env` задаёт другой профиль.

Не удаляйте Docker-тома при обновлении. Сохраняйте прежний `.env`: новые пароли не изменяют пароль уже созданной БД. [Обновление, восстановление и диагностика](docs/OPERATIONS.md).

## Проверки

В проекте есть модульные тесты, проверки контрактов aiogram, HTTP-адаптеров и интеграционные тесты настоящего PostgreSQL. Синтетические сетевые ответы не подтверждают доступность источника, а heartbeat не подтверждает доставку сообщения Telegram. Актуальные результаты и невыполненные этапы следует читать в [матрице проверки](docs/VALIDATION.md); архивные отчёты не заменяют проверку текущего развёртывания.
