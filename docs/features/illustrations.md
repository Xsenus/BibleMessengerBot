# Иллюстрации к стихам

Начиная с 1.4.0 бот хранит готовые иллюстрации в PostgreSQL (`verse_illustrations.image_data`, `bytea`) и использует их в карточках с текстом для `/today`, `/random`, точного одиночного стиха `/read` и ежедневной рассылки. Глава и диапазон сохраняют обычное текстовое представление. Поиск слов показывает текстовые результаты.

Картинка привязана к изданию, книге, главе, стиху и SHA-256 исходного текста. Текст другого перевода не получает чужую иллюстрацию. При отсутствии изображения стих отправляется сразу, а в БД создаётся запись `pending`. В 1.6.0 `illustrator` генерирует также для `/random`, `/today`, `/topic` и точного одиночного стиха `/read` или `/search`. В 1.7.0 текст приходит сразу, а готовая картинка добавляется редактированием исходной карточки через устойчивую очередь. [Связные отрывки и Rich Messages](readings.md). Глава/диапазон и поиск слов не запускают массовую генерацию. [Настройка и бюджет](daily-artwork.md).

В репозитории есть две созданные иллюстрации: Синодальный перевод, Иезекииль 36:13 и Судей 6:16. Происхождение и художественные задания — [manifest.json](../../assets/verses/manifest.json). Это художественные интерпретации, а не исторические фотографии или часть библейского текста.

## Какие запросы получают картинку

| Запрос | Картинка |
|---|---|
| Один стих (`/read Ин 3:16`, `/random`, `/today`, `/topic`) | да; хранится за изданием, книгой, главой, стихом и хешем его текста |
| Целая глава (`/read Пс 22`, «Читать дальше», `/next`) | да, отдельная картинка главы |
| **Диапазон стихов, заданный вручную** (`/read Гал 6:1–10`, `Гал 6:1–9`, `Гал 6:1–5`) | да, **своя картинка на каждую точную последовательность** (см. ниже) |
| Подборка стиха дня / утро–вечер из нескольких стихов | да, но картинка привязана к первому («опорному») стиху отрывка, а не к диапазону целиком |
| Поиск слов | нет |

### Картинки для диапазонов (миграция 033)

- `Гал 6:1–10`, `Гал 6:1–9` и `Гал 6:1–5` — **три разные картинки**. Ключ картинки — издание, книга, глава, первый и последний стих и SHA-256 текста всех стихов диапазона с номерами; поменялась граница или текст — это другая картинка.
- Картинка **закрепляется** за этой точной последовательностью: тот же диапазон у любого пользователя в том же издании получает уже готовую картинку (в течение трёх календарных месяцев, затем создаётся новая версия, старые сохраняются и чередуются, как у стихов и глав).
- Текст приходит сразу, картинка добавляется правкой того же сообщения — как у глав.
- Для создания картинки используется описание **всего** диапазона («главная сцена или образ»), а не только первого стиха.
- Картинка главы запрашивается только адресом целой главы (`/read Гал 6`). Диапазон, который случайно совпал со всей главой (`Гал 6:1–18`), всё равно получает свою картинку-диапазон.
- Один стих, не диапазон, работает как раньше: картинка стиха.
- Каждый **новый** диапазон — это новое задание генерации: оно расходует дневной лимит и бюджет генераторов (бесплатные генераторы из панели расходуют только дневной лимит). Повторный запрос того же диапазона ничего не тратит.
- Остаётся прежнее правило безопасности: если текст стиха диапазона изменился или стих пропал, готовая картинка не показывается и не правится.

## Загрузка готовых файлов

После миграции `005`:

```bash
docker compose exec -T bot python -m app.illustrations_admin add \
  --translation getbible:synodal --book EZK --chapter 36 --verse 13 \
  --file /app/assets/verses/synodal-EZK-36-13.png
docker compose exec -T bot python -m app.illustrations_admin add \
  --translation getbible:synodal --book JDG --chapter 6 --verse 16 \
  --file /app/assets/verses/synodal-JDG-6-16.png
docker compose exec -T bot python -m app.illustrations_admin stats
```

Файл должен быть PNG, JPEG или WebP, размером до 5 MiB. CLI проверяет сигнатуру; оператор должен самостоятельно открыть файл и проверить изображение. Для своего художественного задания передайте `--prompt-file /app/assets/prompt.txt`.

## Очередь для последующей генерации

```bash
docker compose exec -T bot python -m app.illustrations_admin export \
  --limit 20 --output /tmp/illustration-prompts.jsonl
docker compose cp bot:/tmp/illustration-prompts.jsonl ./illustration-prompts.jsonl
```

JSONL содержит ID очереди и задание. Это экспорт, а не запуск генерации. Для постоянной генерации сначала нужны выбранный сервис, API-ключ, бюджет и политика хранения; ключ сохраняется только в приватной конфигурации. Не коммитьте очереди с непроверенными результатами и ключи.

## Хранение и доставка

Общий лимит бинарных данных — 2 GiB; он проверяется под блокировкой PostgreSQL при добавлении. Массовое заполнение всех переводов потребует внешнего файлового хранилища и планирования диска, включая WAL и backups. Количество строк стихов разных изданий не равно количеству уникальных сюжетов.

После первой успешной отправки сохраняется Telegram `file_id` с ID бота. Следующие отправки используют кэш. Если Telegram определённо отверг устаревший `file_id`, файл загружается из БД. Неоднозначная новая отправка не повторяется автоматически. Редактирование фиксированного ID можно безопасно повторить; «message is not modified» подтверждает выполненное изменение. Ошибка записи кэша после принятого фото не вызывает повторной отправки.

В рассылке фотография входит в тот же журнал доставки, что текст. Прогресс и дата следующего запуска меняются только после подтверждённой отправки. Карточки используют Rich Messages: длинный текст и фото находятся в одном сообщении, без ограничения фото-подписи в 1024 единицы UTF-16. Прикладной предел — 24 000 байт UTF-8. Изображения входят в обычный PostgreSQL backup.

## Общая библиотека и версии (1.6.0)

Если для точного текста издания есть картинка моложе трёх **календарных месяцев**, API не вызывается. Срок определяется `generated_at`; обновление Telegram file_id не омолаживает картинку. Ровно на границе трёх месяцев версия считается устаревшей. При отсутствии свежей версии ставится одно общее задание; запросы разных пользователей объединяются.

Старые картинки сохраняются с прежними ID, байтами, prompts, Telegram-кэшем и S3-копиями. Пока обновление готовится или бюджет закончился, доступна старая картинка. Новому пользователю выдаётся уже готовая версия. При повторе сначала выбираются ещё не отправлявшиеся этому чату версии (новые первыми), затем версия с самой давней подтверждённой отправкой. Архив старше трёх месяцев также участвует в чередовании. При единственной версии она повторяется: повторный запрос сам по себе не требует новой платной картинки.

История учитывает только подтверждённые фото Telegram. Каждая карточка сохраняет собственный ID для редактирования; задания генерации одного стиха объединяются. Готовое редактирование фиксируется в `delivery_log`. Начиная с 1.9.0 подтверждённые исходные карточки ждут изображение без срока 24 часа. Одно изображение обновляет все соответствующие карточки, даже после смены настроек чата. Изменённый исходный текст отменяет редактирование; удалённая цель не заменяется новым сообщением. [Правила](persistent-artwork.md). Рассылки по времени получают приоритет над новыми случайными запросами.

Ручной `add` заполняет ожидающую версию либо добавляет новую, сохраняя готовые версии. Лимит 2 GiB учитывает весь архив. Копии S3 содержат бинарный SHA-256, время создания и версию prompt; полные снимки БД включают историю и очередь.


Начиная с 1.10.0 доступен [режим пяти генераторов](../admin/image-providers.md): с 1.10.1 суточные 10 попыток считаются отдельно для каждого сервиса, месячный резерв $10 остаётся общим; при неизвестном ответе новый провайдер может получить отдельный оплачиваемый запрос. Старые неопределённые задания не возобновляются.
