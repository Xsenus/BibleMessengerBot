# База данных и миграции

СУБД: PostgreSQL16 в Compose. `sql/schema.sql` сохранена без изменения байтов относительно1.1.0. `sql/migrations/002_hardening.sql` добавляет новые поля/таблицы/индексы. `schema_migrations` сохраняет SHA256 каждого применённого SQL-файла; изменение уже применённой миграции запрещено.

Основные сущности: `languages`, `translations`, `books`, `verses`; `translation_chapters` — реальные непустые главы в порядке чтения. Для текста сохраняются источник, лицензия/атрибуция, исходный SHA256, закреплённая ревизия, хеш сетки ссылок, результат структурного аудита. `verse_end` связывает объединённый стих; служебные продолжения не публикуются. `ordinal` — индекс только читаемых строк.

`telegram_users`, `telegram_chats`: учётные записи, назначения, UI-язык, язык Библии/издание, часовой пояс, форумная тема, активность, revision. `subscriptions`: режим/время/план/дни успешной доставки, прогресс, revision. `chat_reading_progress`: отдельный ручной прогресс на чат и издание.

`delivery_log`: idempotency_key, ссылка на подписку/назначение, immutable payload, куски, индекс отправки/подтверждения, message IDs, результат, повторы, новые значения прогресса. `operator_events`: решения по неоднозначной доставке. `telegram_rate_limits`: общий лимитер bot+worker. `service_heartbeats`: контроль живости. Старые таблицы справочников тем и планов продолжают использоваться.

## Что считается полнотой

Проверяются фактические книги, непустые главы, строки текста и продолжения диапазонов; существование индексов/счётчиков и их соответствие строкам. `canonical_66_complete` означает присутствие книг и глав 66-книжного ядра по закреплённой нормализованной сетке. `nt_complete` — структура Нового Завета. Это НЕ проверка каждого родного стиха, не сверка рукописей и не утверждение о полноте православного/католического канона. Отсутствующие стихи и объединения могут быть особенностью издания, поэтому они не дописываются и не переводятся нейросетью.

Аудит разбирает отличия от метаданных, но не превращает каталог с обещанием full в подтверждённый полный текст. Физически неполная редакция остаётся partial/nt/ot; режимы, требующие целого корпуса, проверяют реальное покрытие.

## Изменение и обслуживание

Остановите bot/worker/admin перед seed/import/bootstrap; блокировка maintenance отклоняет конкурирующее изменение. Резервная копия содержит и тексты, и персональные ID/прогресс, поэтому является конфиденциальной. Возврат к1.1.0 без резервной копии не поддерживается. Миграция002 сохраняет историю; старые незавершённые отправки без доказательства результата останавливаются для проверки.

Реальный PostgreSQL в среде подготовки не запускался. В `tests/test_postgres_integration.py` есть отдельные исполняемые интеграционные проверки; установщик запускает их на временной тестовой БД до работы с производственной схемой.
