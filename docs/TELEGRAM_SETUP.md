# Telegram: назначения, язык, расписание

## Общие правила

Пользователь сначала открывает бота и отправляет `/start`. Группа: добавьте бота администратором, затем администратор группы вызывает `/settings`. Канал: боту нужно право публикации, а настройки задаются из личного чата реального администратора через `@username` или отрицательный числовой ID. Права проверяются заново при каждой команде и callback. Анонимный администратор не используется как достоверный пользователь; управляйте из личного чата.

Все команды управления группой/каналом требуют прав, даже диагностические. Для темы форума используется одно назначение темы на группу, а не отдельный набор подписок для каждой темы.

## Команды (без target — текущий чат)

```text
/start
/help
/settings [target]
/register target
/language en [target]
/ui ru [target]
/translations [язык] [target]
/translation SOURCE_ID [target]
/subscribe sequential 09:00 Europe/Amsterdam [target]
/subscribe verse 09:00 Europe/Amsterdam [target]
/subscribe topic 09:00 Europe/Amsterdam [target]
/subscribe reading_plan 09:00 Europe/Amsterdam bible-365 [target]
/time 08:30 Europe/Moscow [target]
/thread 123 [target]
/thread off [target]
/pause [target]
/resume [target]
/unsubscribe [mode] [target]
/today [target]
/random [target]
/topic anxiety [target]
/search слово или фраза [target]
/next [target]
/license [target]
/status [target]
/reset confirm [target]
/claim ОДНОРАЗОВЫЙ_КОД
/resolve DELIVERY_ID sent [target]
/resolve DELIVERY_ID retry-duplicate-risk [target]
/resolve DELIVERY_ID cancel [target]
```

Действительные планы: `bible-90`, `bible-180`, `bible-365`, `new-testament-90`, `psalms-150` (сверяйте коды в `data/` и `/help`). Команды показывают допустимые параметры при ошибке. `/topic` выдаёт отрывок указанной темы в текущем запросе; это не изменение темы будущего расписания; название темы в команде — стабильный код. Тематические подборки редакционные, без вычисления «божественного предписания» и без ИИ-переписывания.

## Два независимых канала

```text
/language ru @russian_channel
/subscribe sequential 08:00 Europe/Moscow @russian_channel
/language en @english_channel
/subscribe verse 09:00 Europe/Amsterdam @english_channel
```

Эти команды отправляются боту лично. Текст публикуется на выбранном языке только при наличии проверенного импортированного издания. `/ui` меняет меню без изменения Библии. Конкретное издание выбирается из `/translations`. Замена издания сбрасывает расписанные планы этого чата на начало и останавливает несовместимые планы; ручной `/next` хранит отдельный прогресс каждого издания; она не переносит номер стиха вслепую между разной нумерацией.

Машинные команды и идентификаторы не переводятся; пользовательские сообщения/кнопки переводятся. В Telegram глобальное меню BotCommands зависит от языка клиента; сохранённое меню `/settings` относится к самому назначению. В личном чате нового пользователя исходный интерфейс берётся из языка Telegram, для новой группы/канала исходный язык интерфейса — русский, затем явно настраивается.

Если язык интерфейса не входит в 24 каталога, бот явно сохраняет прежний язык интерфейса. Не все 56 целевых языков корпуса имеют собственный UI. Названия книг локализованы только для русского/английского; в остальных интерфейсах используются коды `GEN`, `JHN` и т. п.

## Расписание и прогресс

По одной подписке каждого режима на чат. Время и часовой пояс хранятся в БД, учитываются переходы летнего времени. Поздний запуск не отправляет все пропущенные дни залпом. Планы рассчитаны на дни успешного чтения: пауза/авария увеличивает календарную длительность. Для длинного плана может потребоваться много сообщений.

`/next` использует сохранённую очередь; прогресс изменяется после подтверждения всех частей. `/pause` сохраняет подтверждённые части, `/resume` продолжает, `/unsubscribe` прекращает публикации. Неопределённая отправка требует решения через `/resolve`; описание рисков — `OPERATIONS.md`.

Потеря прав бота ставит подписки на паузу. Преобразование обычной группы в супергруппу не переносит состояние автоматически: старое назначение останавливается, новое нужно зарегистрировать; сохранённая история остаётся в БД.
