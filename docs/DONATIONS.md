# Добровольная поддержка через Telegram Stars

Чтение Библии, поиск, планы и рассылка остаются бесплатными. В личном чате можно разово поддержать работу проекта Telegram Stars. Поддержка добровольная: она не добавляет платный доступ или особые функции и не включает подписку либо автоматические списания.

## Для пользователя

| Действие | Команда |
|---|---|
| Выбрать сумму | `/donate` или кнопка `⭐ Поддержать` |
| Задать целое число Stars от 1 до 2500 | `/donate 100` |
| Посмотреть свои платежи | `/donations` |
| Прочитать условия | `/terms` |
| Узнать, как обратиться по платежу | `/paysupport` |
| Сохранить обращение оператору | `/paysupport Оплата прошла, но не появилась в истории` |

Все команды поддержки проекта доступны только в личном чате с ботом. Готовые кнопки предлагают 25, 50, 100, 250 и 500 Stars; другую сумму в допустимом диапазоне можно передать команде `/donate`.

После выбора суммы бот показывает условия и кнопку «Согласен, поддержать ⭐ N». Счёт создаётся после нажатия этой кнопки; затем проверьте сумму и подтвердите платёж в интерфейсе Telegram. Отправка команды, выбор суммы и появление счёта сами по себе не означают списание или успешную оплату. `/terms` позволяет отдельно перечитать условия без создания счёта.

`/donations` показывает последние десять собственных оплаченных или возвращённых операций: номер, сумму и статус. Неоплаченный счёт действует один час; для устаревшего создайте новый через `/donate`.

Команда `/paysupport` без текста показывает инструкцию. Непустой текст длиной до 4000 символов сохраняется как обращение в БД проекта с отдельным номером. Укажите номер операции из истории и описание проблемы. Не отправляйте пароли, Telegram-токены, банковские реквизиты или коды входа. Обращения рассматривает оператор проекта; регистрация заявки не означает, что она уже прочитана, и не запускает автоматический возврат.

## Обработка счёта

Счёт использует валюту `XTR`, одну позицию `LabeledPrice` с целым числом Stars и пустой `provider_token`. Отдельный токен платёжного провайдера для этого сценария не нужен. Операция связана с пользователем, суммой и уникальным payload; перед checkout проверяются её состояние и срок действия.

Telegram требует ответить на `pre_checkout_query` в течение 10 секунд. Одобрение checkout разрешает продолжить оплату; обычное подтверждение оплаты приходит через `successful_payment`. Приложение сохраняет `telegram_payment_charge_id` и использует уникальность идентификаторов, чтобы повторно доставленное событие не создавало второй платёж. Основной контракт описан в [официальном руководстве Telegram Stars](https://core.telegram.org/bots/payments-stars).

Срок неоплаченного счёта проверяется до checkout. Поздно доставленное подтверждение уже успешной оплаты обрабатывается и после истечения этого срока: реальный платёж не теряется из-за задержки события. История показывает только операции самого пользователя; Telegram charge ID хранится для служебного разбора и возврата.

Фоновая сверка с реестром транзакций Telegram помогает учесть пропущенное подтверждение оплаты или возврата для уже известного локального заказа. Она проверяет пользователя, сумму и payload; это не автоматическое рассмотрение обращений `/paysupport`. Сверка не восстанавливает неизвестные заказы, потерянные при возврате к старому dump, поэтому надёжные резервные копии платёжного журнала необходимы.

Платёжный журнал и обращения находятся в PostgreSQL и входят в обычный backup проекта. В нём сохраняются идентификатор пользователя, сумма, состояние операции, Telegram charge ID и необходимые служебные данные. Не публикуйте dump или необработанный вывод платёжного CLI.

## Работа оператора

Оператор обязан регулярно просматривать обращения. В этой версии не обещаны автоматический мониторинг, уведомления администратору или автоматическая обработка возвратов. Из каталога проекта на сервере:

```bash
# Обращения по оплате.
docker compose run --rm --no-deps bootstrap python -m app.donations_admin support

# Журнал платежей.
docker compose run --rm --no-deps bootstrap python -m app.donations_admin payments

# Текущий баланс Stars у Telegram.
docker compose run --rm --no-deps bootstrap python -m app.donations_admin balance

# Сверить до 20 страниц транзакций с локальным журналом.
docker compose run --rm --no-deps bootstrap python -m app.donations_admin reconcile --pages 20
```

Сопоставьте заявку, пользователя и подтверждённую операцию. CLI использует серверный `.env`; передавать токен в командной строке не нужно. Не изменяйте финансовые записи вручную, чтобы имитировать оплату или возврат.

`support` показывает до 100 открытых обращений, `payments` — последние 100 подтверждённых платежей. `balance` только читает баланс. `reconcile` получает подтверждённые операции Telegram и дополняет платёжный журнал известных заказов; он не списывает Stars и не инициирует возврат. Обычный фоновый цикл примерно каждые пять минут сверяет последние 100 транзакций и до 500 более старых, сохраняя позицию обхода истории.

Для ответа на обращение подготовьте на сервере UTF-8-файл `reply.txt` с готовым текстом длиной от 1 до 3500 символов. Следующие команды передают файл в работающий контейнер с правами его пользователя, затем отправляют **одно реальное личное сообщение** автору заявки. Замените `TICKET_ID` её номером и проверьте текст до отправки:

```bash
docker compose exec -T bot sh -c 'umask 077; cat > /tmp/donation-support-reply.txt' < reply.txt
docker compose exec -T bot python -m app.donations_admin support-reply TICKET_ID --message-file /tmp/donation-support-reply.txt
docker compose exec -T bot rm -f /tmp/donation-support-reply.txt
```

Ответ отправляется как обычный текст без HTML-разметки; после подтверждения отправки заявка закрывается. При сетевой неопределённости **не повторяйте команду вслепую**: сообщение могло дойти, даже если CLI сообщил об ошибке. Проверьте состояние заявки и доставку до решения о повторе.

Для возврата замените `ORDER_ID` реальным идентификатором **операции**, а не номером обращения:

```bash
docker compose run --rm --no-deps bootstrap python -m app.donations_admin refund ORDER_ID --confirm
```

Команда выполняет возврат Stars через [официальный метод `refundStarPayment`](https://core.telegram.org/bots/api#refundstarpayment). Возврат — реальное изменение платёжной операции; перед `--confirm` проверьте выбранный платёж. Успешное создание заявки `/paysupport` не подтверждает возврат. При ошибке API изучите состояние операции и ответ CLI, не отмечайте её возвращённой вручную.

После рассмотрения обращения замените `TICKET_ID` его фактическим номером:

```bash
docker compose run --rm --no-deps bootstrap python -m app.donations_admin support-close TICKET_ID
```

`support-close` меняет состояние заявки без сообщения и без возврата Stars. Используйте его для уже рассмотренного обращения; для отправки ответа с последующим закрытием предназначен `support-reply`.

## Обновление и восстановление

Платёжные таблицы добавляются миграцией `004`; используйте штатный порядок backup → остановка приложения → миграции → проверки → запуск. Миграция не требует повторной загрузки Библии. После восстановления старого dump необходимо сверить платежи и возвраты с Telegram: восстановленная БД может не знать о более поздних реальных операциях. Не воспроизводите их повторной оплатой или ручной заменой статусов.

## Граница проверки

Документация описывает платёжный сценарий приложения. **Реальная платёжная транзакция и реальный возврат Stars в ходе подготовки не выполнялись.** Создание счёта, модульные проверки и тесты БД не подтверждают списание или возврат в боевой среде. Фактические результаты проверок публикуются отдельно в отчёте соответствующего релиза; пользовательское подтверждение оплаты для тестирования нельзя предполагать автоматически.
