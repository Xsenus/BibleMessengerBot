# Диагностика

Начните с `docker compose ps`, `docker compose logs --tail=100 <service>` и полного аудита: `docker compose run --rm --no-deps bootstrap python -m app.cli audit`. Не публикуйте полный `.env` или вывод Compose с секретами.

| Симптом | Проверка и действие |
|---|---|
| `POSTGRES_PASSWORD is required` | Заполните приватный `.env`; запускайте Compose из правильного каталога. |
| БД уже существует, `.env` потерян | Восстановите исходный конфиг. Генерация нового `POSTGRES_PASSWORD` не меняет пароль в томе. |
| `password authentication failed` | Проверьте согласованность `POSTGRES_PASSWORD` и URI `DATABASE_URL`; не удаляйте том. |
| `Stop bot, worker and admin before ... maintenance` | Работает runtime-блокировка. Используйте `fill_database.sh` либо после backup остановите три службы этого проекта. |
| `Applied migration was modified` | Восстановите оригинальный применённый SQL; дальнейшее изменение оформляйте новой миграцией. |
| Нет оповещений в Telegram | Нужен владелец (`/start` с `OWNER_CLAIM_CODE`). Проверьте `docker compose --profile maintenance run --rm --no-deps alerts`: вывод JSON показывает активные оповещения. |
| `/metrics` отвечает 401 | HTTP Basic: пользователь `admin`, пароль `ADMIN_API_KEY` (не менее 24 символов). |
| Растёт `delivery_log` | Запустите `housekeeping` (`--dry-run` покажет объём); см. [MONITORING](monitoring.md#хранение-данных-retention). |
| `/ready` возвращает 503 | Проверьте аудит, наличие фактических изданий и `REQUIRED_LANGUAGES`. Profile `none` — специальный режим без требования корпуса, не способ выдать пустую БД за готовую. |
| Импорт завершился кодом 2 | Это частичный результат. Читайте полный отчёт, ошибки источников и список `held`; успешные издания могли сохраниться. |
| Источник недоступен / таймаут | Проверьте DNS, исходящий HTTPS, время сервера и место в кэше. Повторите тот же импорт; не отключайте TLS/лицензионные проверки. |
| `held` при повторном импорте | Текст источника изменился. Существующее издание защищено, особенно при наличии прогресса/подписок. `--replace-existing` разрешён только для неиспользуемых записей. |
| Недостаточно места | Различайте кэш, БД и backups. Освобождайте только известные файлы своего проекта; ограничьте языки/издания. Не удаляйте работающий кэш или том БД. |
| Admin не открывается снаружи | Это штатный loopback-bind. Используйте SSH-туннель и `/admin`, логин `admin`, ключ из `.env`. |
| `/admin` или `/api/stats` возвращает 401 | Ключ должен совпадать с `ADMIN_API_KEY` и иметь не менее 24 символов. API использует `X-Admin-Key`, страница — HTTP Basic. |
| Изменённый `.env` не подхватился | `docker compose restart` оставляет окружение прежним; пересоздайте нужные службы через `up -d --no-deps --force-recreate`. |
| Bot не запускается / неверный токен | Проверьте токен через BotFather; остановите другую установку с тем же токеном. Не включайте токен в URL диагностического issue. |
| Команда канала запрещена | Бот и отправитель должны быть администраторами, бот должен иметь право публикации. Управляйте каналом из личного чата. |
| Бот не отвечает в группе | Проверьте права бота, синтаксис `/command@bot_username`, журналы и состояние bot. Анонимный отправитель должен управлять из личного чата. |
| Язык/издание не найдено | Смотрите `/translations` и реальный отчёт импорта; профиль языков не гарантирует наличие перевода. |
| Тематический режим недоступен | Для native-нумерации getBible/HelloAO проверенного сопоставления тематических ссылок нет; используйте другие режимы. |
| ВКонтакте: бот не отвечает | `docker compose --profile vk ps`, `logs vkbot`. Проверьте `VK_BOT_TOKEN`, `VK_GROUP_ID`, что сообщения сообщества включены и у ключа есть права «сообщения». Метрика `bible_vk_inbox_pending` растёт — потребитель не успевает или остановлен. |
| ВКонтакте: пользователь не получает рассылку | Он запретил сообщения сообществу (`message_deny`): чат отключён автоматически; вернётся после `message_allow`. |
| Объявление не ушло в срок | Панель → «Объявления»: статус и «следующий запуск». Служба `composer` должна быть `healthy`; опоздавший больше чем на час запуск пропускается (`skipped_late`). |
| Источник не собирает посты | Он должен быть включён (по умолчанию выключен). Telegram: у бота нужны права; в группах отключите Privacy Mode. ВКонтакте: включите события стены и права на записи. |
| Видеоканал с ошибкой | Панель → «Видео»: поле ошибки. Интервал опроса растёт при сбоях (до 6 часов). Для ВКонтакте нужен `VK_SERVICE_TOKEN`. |
| Генератор картинок: `auth`, `rate_limited`, `response_invalid` | Панель → «Генераторы картинок» → «Проверить». См. [image-providers](../admin/image-providers.md#не-получается). |
| `secrets_key_missing` в панели | Задайте `SECRETS_KEY` или `ADMIN_API_KEY` (24+ символа) и пересоздайте службу. После смены ключа заново введите ключи генераторов. |
| Панель: «Неверный ключ» | Ключ должен совпадать с `ADMIN_API_KEY` из `.env` службы admin. Проверьте туннель SSH и порт `ADMIN_HOST_PORT`. |
| `uncertain` / `failed` | Проверьте сообщения непосредственно в чате, затем примените `/resolve`; инструкция в [operations.md](operations.md#неопределённая-доставка), либо панель → «Доставки». |
| Публикация не пришла в заданную минуту | Проверьте timezone и `next_run_at`, heartbeat worker, паузу, незавершённые задания, права бота и лимиты Telegram. |
| Контейнер `unhealthy`, но не перезапускается | Healthcheck — сигнал состояния, а не самостоятельная политика перезапуска. Изучите логи и heartbeat. |
| После restore появились старые задания | Оставьте worker остановленным, сопоставьте восстановленную очередь с Telegram; старый backup не знает о более поздних публикациях. |

Если ошибка сохраняется, создайте issue с commit, окружением, командой и очищенным отчётом. Не заменяйте неудавшуюся проверку ручным запуском рассылки до понимания причины.
