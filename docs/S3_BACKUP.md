# Резервные копии в S3 (1.5.0)

В `.env` задаются `S3_ENDPOINT`, `S3_REGION`, `S3_BUCKET`, `S3_ACCESS_KEY`, `S3_SECRET_KEY` и `BACKUP_ENCRYPTION_KEY`. Ключ шифрования — 32 случайных байта в виде 64 hex-символов. Храните независимую приватную копию вне VPS и вне публичного Git. Без этого ключа восстановление зашифрованной БД невозможно.

Используются HTTPS, SigV4 и path-style; для Hostkey NL регион `nl`. [Документация Hostkey](https://hostkey.com/documentation/technical/exist_server_using/s3/). Приложение записывает только префикс `bible-messenger/v1/` указанного бакета, не меняет ACL и политики других объектов.

## Что сохраняется

`bash backup.sh` создаёт согласованный custom-format pg_dump, включая пользователей, расписания, очередь, библейские тексты и бинарные изображения. Перед загрузкой весь dump шифруется AES-256-GCM с новым nonce; затем проверяются HEAD и полный GET с SHA-256. Квитанция записывается в БД только после проверки. После успешной облачной проверки локально сохраняются до семи собственных снимков в пределах 4 GiB, минимум последний. Чужие файлы не очищаются. При ошибке S3 ротация не выполняется: контролируйте свободный диск и устраните причину ошибки. `BACKUP_LOCAL_ONLY=1 bash backup.sh` делает только локальный снимок.

Отдельный цикл `illustrator` копирует готовые изображения и JSON-манифесты с изданием, источником, адресом, SHA текста и prompt в S3; ошибка повторяется через 30 секунд, исходник остаётся в БД. Изображения не зашифрованы приложением, поэтому бакет должен оставаться приватным. Объекты имеют уникальные ключи; автоматического удаления старых облачных копий нет. Контролируйте объём и оплачиваемое хранение.

## Восстановление

```bash
docker compose --profile maintenance run --rm -T --no-deps backup python -m app.backup_admin status
docker compose --profile maintenance run --rm -T --no-deps backup python -m app.backup_admin download-db --key bible-messenger/v1/database/EXACT_OBJECT_KEY --output /app/backups/recovered.dump
```

Команда скачивает, проверяет SHA-256 и аутентифицированно расшифровывает; существующий выходной файл не перезаписывает и рабочую БД не меняет. Перед восстановлением проверьте `pg_restore --list` и восстановите снимок в отдельную временную PostgreSQL-БД. Сравните количество изданий/стихов/иллюстраций и хеши изображений. Только после этого используйте существующий `restore.sh`, который явно останавливает службы и требует подтверждения замены рабочей БД.

Отдельные картинки восстанавливаются через манифест и `app.illustrations_admin add`, проверяющий текущий текст стиха; полный dump восстанавливает их автоматически. Секреты `.env` в dump не входят: нужны отдельные приватные копии конфигурации, ключа шифрования и сведения о commit приложения.

На действующем VPS ежедневный systemd timer запускает `backup.sh` в 01:30–01:35 Asia/Novosibirsk. Для новой установки скопируйте units из `deploy/` по [OPERATIONS.md](OPERATIONS.md); путь проекта и часовой пояс можно изменить в копии units. Проверяйте `systemctl list-timers --all bible-messenger-backup.timer` и журнал соответствующей service. Наличие timer не заменяет периодическую пробу восстановления; фактические результаты приведены в текущем аудите.
