# Озвучка библейского чтения

Новые библейские сообщения получают аудиоплеер прямо под текстом. Для ручных команд `speaker` создаёт недостающую запись и обновляет исходное сообщение. Для стиха дня и утреннего/вечернего/тематического расписания картинка и записи всех доступных языков готовятся **до первоначальной отправки**. [Подготовка расписаний](PREPARED_SCHEDULES.md). Дополнительных сообщений с аудиофайлами нет. Воспроизведение запускает пользователь.

При выборе языка меняются текст и дорожка. Пока новая запись готовится, прежняя убирается, чтобы русский текст не воспроизводился греческим голосом. Возврат к готовому варианту использует кэш. Запоздавшая генерация другого языка не подменяет текущий выбор. Поздняя картинка также сохраняет актуальную озвучку. У длинного перевода со страницами аудио соответствует открытой странице; у длинной главы из нескольких сообщений — тексту конкретной части.

Озвучиваются слова сохранённого перевода. Заголовки, служебные подписи, номера стихов в жирных метках и лицензионный подвал не читаются; числа внутри самого стиха сохраняются. Все записи помечены как синтетическая озвучка. Это не запись диктора и не гарантия правильного ударения в каждом имени.

## Бесплатный режим

По умолчанию `AUDIO_ENABLED=true`, `AUDIO_PROVIDER=free`. Русский (`rus`) читает локальный нейросетевой Piper `ru_RU-denis-medium`. Латынь (`lat`) и древнегреческий (`grc`, кнопка «Ἑλληνική») используют отдельные VITS-модели Meta MMS. Эти три языка больше не переключаются на роботизированный eSpeak при сбое. Ошибка сохраняется в задании с ограниченными повторными попытками. Готовая старая запись остаётся в Telegram до замены; при ручной смене языка действует обычное удаление прежней дорожки.

Модели работают на CPU, без API-ключа, оплаты запроса и передачи текста внешнему сервису. Они синтетические: ударения имён и конкретная традиция произношения древних языков не гарантируются. Латинские `æ/œ/j` нормализуются для голосовой модели в `ae/oe/i`, чтобы её словарь не удалял буквы; видимый текст Библии остаётся исходным. Длинный текст разбивается на небольшие части по границам фраз, без обрезания и перестановки слов.

Весовые файлы (~354 MB) устанавливаются в `AUDIO_MODELS_PATH=/app/cache/tts` на общем томе `source_cache`. [Манифест](../app/data/speech-models.json) фиксирует ревизии, размеры и SHA-256 каждого файла. Установка проверяет хеши; загрузка модели во время чтения не выполняется. Используются safetensors/ONNX, загрузка удалённого Python-кода запрещена. Синтез выполняется отдельным процессом с ограничением времени, после завершения память освобождается. `speaker` ограничен 1.5 GiB RAM и одним CPU. Помимо весов нужны CPU PyTorch, Transformers и ONNX Runtime; они включены в образ.

```bash
docker compose run --rm --no-deps bootstrap python -m app.neural_audio_admin prepare
docker compose exec -T speaker python -m app.neural_audio_admin status
```

Смена профиля автоматически создаёт новый общий кэш для существующих языковых карточек. После генерации исходные сообщения обновляются через постоянную очередь. Старые MP3 не удаляются, платные попытки не расходуются, выбранный язык/картинка/прогресс не меняются. MP3 входят в зашифрованные копии БД; скачанные веса можно восстановить из фиксированного манифеста.

Для остальных современных языков остаются [Edge](https://github.com/rany2/edge-tts) и локальный eSpeak как резерв. Текст такого публичного библейского отрывка передаётся онлайн-сервису; пользовательские идентификаторы и секреты не передаются. Древнееврейский читается современным еврейским голосом. `AUDIO_PROVIDER=neural` ограничивается тремя локальными нейросетевыми языками, `edge` и `espeak` доступны как явные дополнительные режимы. Автоматическая замена eSpeak относится к режиму `free`.

## Лицензии голосов

Код Piper распространяется по GPL-3.0, русский голос Denis обучен на CC0-данных; карточка модели сохранена рядом с весами. Модели [Meta MMS Latin](https://huggingface.co/facebook/mms-tts-lat) и [Meta MMS Ancient Greek](https://huggingface.co/facebook/mms-tts-grc) созданы Vineel Pratap и соавторами (Meta AI, *Scaling Speech Technology to 1,000+ Languages*) и опубликованы под **CC BY-NC 4.0 — для некоммерческого использования**. Карточки авторов и ссылки на условия сохранены в кэше. Модели не дообучаются; текст нормализуется только при синтезе. Лицензия MIT приложения не заменяет лицензии моделей. Для коммерческого применения выберите другой режим с подходящими условиями. Это отдельные условия голосовых моделей, а не изменение политики импорта библейских текстов.

## Дополнительная ИИ-озвучка OpenAI

[Официальный Speech API](https://developers.openai.com/api/docs/guides/text-to-speech) поддерживается как отдельный необязательный режим. Он не включается автоматически после отказа бесплатного сервиса. В приватном `.env` нужны все настройки:

```dotenv
AUDIO_PROVIDER=openai
AUDIO_PAID_ENABLED=true
AUDIO_OPENAI_API_KEY=YOUR_PRIVATE_KEY
AUDIO_OPENAI_MODEL=gpt-4o-mini-tts
AUDIO_OPENAI_VOICE=marin
AUDIO_PAID_MONTHLY_MAX_CHARACTERS=30000
AUDIO_PAID_DAILY_MAX_CHARACTERS=3000
```

Числа выше — пример лимитов объёма, а не прогноз стоимости. Фактическое списание зависит от текущего тарифа и ответа провайдера. Если отдельный ключ пуст, используется `OPENAI_API_KEY`. По умолчанию разрешение выключено, оба лимита нулевые: одного существующего ключа генерации картинок недостаточно для платной озвучки. Бюджет и попытки изображений не используются и не меняются.

Перед запросом весь текст атомарно резервируется по числу символов на UTC-день и месяц. Длинные записи разделяются на запросы до 3000 символов и объединяются в один MP3 без обрезания текста. Ошибка с неоднозначным результатом сохраняет резерв, получает состояние `uncertain` и не повторяется автоматически. Прерывание платной генерации при перезапуске также считается неоднозначным. Бесплатная генерация допускает ограниченные повторы.

После изменения режима перезапустите службы; новый запрос/повторный выбор языка создаёт вариант нового режима:

```bash
docker compose up -d --force-recreate --no-deps bot worker speaker
```

## Хранение и эксплуатация

Миграция 013 добавляет `reading_audio`, `audio_generation_attempts` и связи `reading_cards.audio_id/audio_sent_id`. Миграция 014 добавляет версию голосового профиля. Кэш общий для одинакового текста, языка, режима, профиля и параметров платного голоса. В PostgreSQL сохраняются MP3, длительность, происхождение, подтверждённый Telegram file ID и состояние задания. Записи входят в обычные зашифрованные резервные копии БД/S3. Лимит одной записи 20 MiB/час, всего кэша 1 GiB; при заполнении генерация ожидает освобождения места. Автоматического удаления истории нет.

`speaker` работает отдельно от отправителя и иллюстратора, с блокировкой единственного экземпляра и собственным heartbeat. FFmpeg проверяет наличие аудиопотока и длительность; локальные процессы ограничены временем. Ручные команды не блокируются ожиданием аудио; расписания стиха дня, утреннего/вечернего и тематического чтения ожидают готовность всех предлагаемых языков. Готовая запись обновляет все ожидающие подтверждённые карточки, где всё ещё выбран именно этот вариант. Редактирование проходит через постоянную очередь и общую блокировку чата; неоднозначный ответ Telegram допускает повтор того же редактирования без новых сообщений.

```bash
docker compose ps
docker compose logs --tail=100 speaker worker
docker compose exec -T speaker python -m app.healthcheck speaker
```

Старые карточки с языковыми кнопками получают озвучку автоматически; произвольные сообщения до появления `reading_cards` не восстанавливаются по догадке. Удалённое пользователем сообщение не заменяется новым. У бота должны быть права отправлять аудио в соответствующую группу/канал. Установка/обновление/восстановление учитывают новую службу. Полное отключение новых аудиозаписей — `AUDIO_ENABLED=false` с перезапуском служб; ранее отправленные файлы из истории Telegram это не удаляет.
