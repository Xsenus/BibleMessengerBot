# Озвучка библейского чтения

Новые библейские сообщения получают аудиоплеер прямо под текстом. Текст и картинка отправляются сразу; если записи ещё нет, отдельная служба `speaker` создаёт её и редактирует исходное сообщение. Дополнительных сообщений с аудиофайлами нет. Запись не включается автоматически — воспроизведение запускает пользователь.

При выборе языка меняются текст и дорожка. Пока новая запись готовится, прежняя убирается, чтобы русский текст не воспроизводился греческим голосом. Возврат к готовому варианту использует кэш. Запоздавшая генерация другого языка не подменяет текущий выбор. Поздняя картинка также сохраняет актуальную озвучку. У длинного перевода со страницами аудио соответствует открытой странице; у длинной главы из нескольких сообщений — тексту конкретной части.

Озвучиваются слова сохранённого перевода. Заголовки, служебные подписи, номера стихов в жирных метках и лицензионный подвал не читаются; числа внутри самого стиха сохраняются. Все записи помечены как синтетическая озвучка. Это не запись диктора и не гарантия правильного ударения в каждом имени.

## Бесплатный режим

По умолчанию `AUDIO_ENABLED=true`, `AUDIO_PROVIDER=free`. Для современных языков используется [edge-tts](https://github.com/rany2/edge-tts), вызывающий нейросетевые голоса Microsoft Edge без API-ключа. Для русского выбран `ru-RU-DmitryNeural`, для современного греческого — `el-GR-NestorasNeural`. Для остальных поддерживаемых языков назначены собственные голоса. Текст публичного библейского отрывка передаётся этому онлайн-сервису; пользовательские идентификаторы, токен Telegram и ключи генераторов не передаются. Доступность бесплатного сервиса и его интерфейс могут меняться.

Резерв — локальный [eSpeak NG](https://github.com/espeak-ng/espeak-ng), не требующий интернета или платы за запросы. Он менее естественный, зато позволяет читать при отказе онлайн-сервиса. Для `grc` сразу используется отдельный голос древнегреческого `grc`, для латыни — `la`; древнееврейский читается еврейским голосом. Древнегреческое и древнееврейское произношение условное, оно не обещает академически проверенную реконструкцию или конкретную церковную традицию.

Также можно выбрать `AUDIO_PROVIDER=edge` без локального резерва либо `AUDIO_PROVIDER=espeak` для полностью локальной озвучки. Неподдерживаемый язык не заменяется английским. Расходов API в бесплатном режиме нет; CPU, диск и трафик оплачиваются в рамках VPS.

## Дополнительная ИИ-озвучка OpenAI

[Официальный Speech API](https://developers.openai.com/api/docs/guides/text-to-speech) поддерживается как отдельный необязательный режим. Он не включается автоматически после отказа бесплатного сервиса. В приватном `.env` нужны все настройки:

```dotenv
AUDIO_PROVIDER=openai
AUDIO_PAID_ENABLED=true
AUDIO_OPENAI_API_KEY=YOUR_PRIVATE_KEY
AUDIO_OPENAI_MODEL=gpt-4o-mini-tts
AUDIO_OPENAI_VOICE=marin
AUDIO_PAID_MONTHLY_MAX_CHARACTERS=30000
AUDIO_PAID_DAILY_MAX_CHARACTERS=3000
```

Числа выше — пример лимитов объёма, а не прогноз стоимости. Фактическое списание зависит от текущего тарифа и ответа провайдера. Если отдельный ключ пуст, используется `OPENAI_API_KEY`. По умолчанию разрешение выключено, оба лимита нулевые: одного существующего ключа генерации картинок недостаточно для платной озвучки. Бюджет и попытки изображений не используются и не меняются.

Перед запросом весь текст атомарно резервируется по числу символов на UTC-день и месяц. Длинные записи разделяются на запросы до 3000 символов и объединяются в один MP3 без обрезания текста. Ошибка с неоднозначным результатом сохраняет резерв, получает состояние `uncertain` и не повторяется автоматически. Прерывание платной генерации при перезапуске также считается неоднозначным. Бесплатная генерация допускает ограниченные повторы.

После изменения режима перезапустите службы; новый запрос/повторный выбор языка создаёт вариант нового режима:

```bash
docker compose up -d --force-recreate --no-deps bot worker speaker
```

## Хранение и эксплуатация

Миграция 013 добавляет `reading_audio`, `audio_generation_attempts` и связи `reading_cards.audio_id/audio_sent_id`. Кэш общий для одинакового текста, языка, режима и параметров платного голоса. В PostgreSQL сохраняются MP3, длительность, происхождение, подтверждённый Telegram file ID и состояние задания. Записи входят в обычные зашифрованные резервные копии БД/S3. Лимит одной записи 20 MiB/час, всего кэша 1 GiB; при заполнении генерация ожидает освобождения места. Автоматического удаления истории нет.

`speaker` работает отдельно от отправителя и иллюстратора, с блокировкой единственного экземпляра и собственным heartbeat. FFmpeg проверяет наличие аудиопотока и длительность; локальные процессы ограничены временем. Текст не блокируется ожиданием аудио. Готовая запись обновляет все ожидающие подтверждённые карточки, где всё ещё выбран именно этот вариант. Редактирование проходит через постоянную очередь и общую блокировку чата; неоднозначный ответ Telegram допускает повтор того же редактирования без новых сообщений.

```bash
docker compose ps
docker compose logs --tail=100 speaker worker
docker compose exec -T speaker python -m app.healthcheck speaker
```

Старые карточки с языковыми кнопками получают озвучку автоматически; произвольные сообщения до появления `reading_cards` не восстанавливаются по догадке. Удалённое пользователем сообщение не заменяется новым. У бота должны быть права отправлять аудио в соответствующую группу/канал. Установка/обновление/восстановление учитывают новую службу. Полное отключение новых аудиозаписей — `AUDIO_ENABLED=false` с перезапуском служб; ранее отправленные файлы из истории Telegram это не удаляет.
