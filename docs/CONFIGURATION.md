# Конфигурация

Основной пример — [`.env.example`](../.env.example). Docker Compose передаёт его значения в контейнеры через `.env`; Python сам файл `.env` не загружает. При запуске Python без Docker задавайте переменные окружения средствами своей оболочки. После изменения конфигурации пересоздайте затронутые контейнеры (`docker compose up -d --no-deps --force-recreate bot worker admin`); простой `restart` не перечитывает окружение контейнера.

## Секреты и подключение

| Переменная | Назначение |
|---|---|
| `BOT_TOKEN` | Токен BotFather. Требуется процессам `bot` и `worker`; скачивание/импорт и admin допускают отсутствие токена. |
| `OWNER_CLAIM_CODE` | Одноразовый код регистрации владельца командой `/claim` в личном чате. Не даёт обходить права Telegram. |
| `POSTGRES_DB`, `POSTGRES_USER` | Имя БД и пользователя контейнера PostgreSQL; обычно `biblebot`. |
| `POSTGRES_PASSWORD` | Пароль, используемый при первом создании PostgreSQL-тома. Изменение `.env` не меняет пароль существующей роли. |
| `DATABASE_URL` | Строка `postgresql://USER:PASSWORD@postgres:5432/DATABASE` в Compose. Для локального Python нужен реально доступный адрес БД. |
| `ADMIN_API_KEY` | Пароль `/admin` и значение заголовка `X-Admin-Key` для `/api/stats`; минимум 24 символа. |
| `ADMIN_HOST_PORT` | Порт хоста для локальной административной страницы, по умолчанию `8080`. |

Установщик генерирует случайные секреты. При ручной настройке удобны случайные hex-значения (`openssl rand -hex 32`): они не требуют специального кодирования в URI. Иные специальные символы в пароле `DATABASE_URL` должны быть корректно закодированы. Согласуйте пользователя, пароль и имя БД во всех переменных. Не печатайте `docker compose config` без `--quiet`: полный вывод может содержать секреты.

`ADMIN_BIND` и `ADMIN_PORT` читаются в Settings, но штатная команда Compose явно задаёт Uvicorn `0.0.0.0:8080` внутри контейнера. Для изменения публикации на хосте используется `ADMIN_HOST_PORT`. `PUBLIC_BASE_URL` необязателен; установка использует long polling, без настройки webhook по этой переменной.

## Импорт Библии

| Переменная | По умолчанию | Поведение |
|---|---|---|
| `BIBLE_PROFILE` | `all-open` | `core`, `extended`, `all-open` или `none`; подробнее в [профилях](TRANSLATION-PROFILES.md). |
| `BIBLE_SOURCES` | `biblenlp,getbible,helloao` | Уникальный список поддерживаемых источников и порядок обработки. |
| `BIBLENLP_REVISION` | `latest` | Разрешить и закрепить один commit на запуск или задать точный 40-символьный SHA. |
| `IMPORT_LANGUAGES` | пусто | Дополнительный список языков через запятую, например `ru,en`. |
| `IMPORT_EDITIONS` | пусто | Точные идентификаторы `source:id`; источник должен быть включён. |
| `MAX_EDITIONS_PER_LANGUAGE` | `2` | Максимум успешных изданий языка в каждом источнике для `core`/`extended`; не действует в `all-open`. |
| `IMPORT_ON_START` | `true` | Импорт во время bootstrap. При `false` применяется схема и проверяется уже имеющийся корпус. |
| `REQUIRED_LANGUAGES` | `rus,eng` | Для каких языков readiness требует полное структурное 66-книжное ядро. Профиль `none` отключает это требование. |
| `SOURCE_CACHE_DIR` | `/app/cache` | Каталог исходных файлов и отчётов; в Compose находится в постоянном томе `source_cache`. |
| `IMPORT_BATCH_SIZE` | `2000` | Размер порции записи строк; минимум 100. |
| `DOWNLOAD_TIMEOUT_SECONDS` | `180` | Таймаут сетевой операции в секундах. |
| `IMPORT_RETRIES` | `5` | Максимум попыток запроса. |
| `IMPORT_REQUESTS_PER_SECOND` | `2` | Ограничение запросов к хосту источника. |
| `IMPORT_MIN_FREE_MB` | `1024` | Резерв свободного места на файловой системе кэша. |
| `IMPORT_MAX_CACHE_MB` | `30720` | Бюджет кэша; это не бюджет PostgreSQL, Docker и резервных копий. |
| `IMPORT_MAX_FILE_MB` | `128` | Максимальный размер скачиваемого файла. |
| `ALLOW_RESTRICTED_LICENSES`, `ALLOW_UNKNOWN_LICENSES` | `false` | Должны оставаться `false`; текущая версия отвергает включение обхода политики. |

Лимиты `*_MB` используют множители 1024. CLI-фильтры перекрывают соответствующие переменные; `--languages` и `--editions` пересекаются. `fill_database.sh` по умолчанию явно выбирает `all-open`; для иного профиля передайте `--profile`. Подробнее — [импорт](MULTISOURCE_IMPORT_RU.md).

## Расписание и процессы

| Переменная | По умолчанию в Settings | Назначение |
|---|---|---|
| `DEFAULT_TIMEZONE` | `Europe/Amsterdam` | IANA timezone для новых назначений, например `Europe/Moscow` или `Asia/Novosibirsk`. |
| `DEFAULT_SEND_TIME` | `09:00` | Время новой подписки в формате `HH:MM`. |
| `WORKER_POLL_SECONDS` | `15` | Интервал поиска работы. Установщик может явно задать меньшее значение. |
| `TELEGRAM_GLOBAL_RATE_PER_SECOND` | `20` | Общий лимит отправки, не больше 20. |
| `TELEGRAM_CHAT_RATE_PER_SECOND` | `1` | Лимит на чат, не больше 1. |
| `MAX_MESSAGE_LENGTH` | `3900` | Лимит части сообщения с учётом форматирования; максимум 4096. |
| `LOG_LEVEL` | `INFO` | Уровень журналирования приложения. |

Изменение значений по умолчанию не переписывает уже сохранённые настройки чатов и подписок. Меняйте их через `/time`, `/language`, `/translation` и `/subscribe` для нужного назначения.

Имя, описания, команды и изображения профиля задаются в коде/ресурсах, а не дополнительными переменными `.env`: [BRANDING.md](BRANDING.md).
