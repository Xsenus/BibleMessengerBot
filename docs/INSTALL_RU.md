# Установка на VPS

## Требования и изоляция

Автоматический `install.sh` поддерживает Ubuntu/Debian, Bash, доступ в интернет и `sudo`. При отсутствии Docker установщик добавляет официальный репозиторий Docker и устанавливает Engine/Compose системными пакетами. На сервере с уже существующими контейнерами сначала проверьте версии и планируемые изменения пакетов. Домен и входящий публичный HTTP-порт для Telegram long polling не требуются.

Размещайте проект в собственной папке, например `/opt/bible-messenger-bot`. Compose использует имя проекта `bible-messenger-bot`, отдельную сеть и тома `postgres_data`/`source_cache`. Не запускайте вторую независимую копию с тем же именем проекта: она будет работать с теми же ресурсами. Для отдельного стенда задайте отдельный `COMPOSE_PROJECT_NAME` и другой `ADMIN_HOST_PORT`; сохраняйте это имя при всех операциях со стендом.

Размер CPU/RAM/диска для всех доступных языков заранее не гарантируется. Объём зависит от источников и числа изданий. Лимит кэша по умолчанию — 30 GiB; PostgreSQL, индексы, образы, журналы и резервные копии требуют дополнительного места. Начните с русского и английского или конкретных изданий, затем оцените фактический объём.

## Получение кода

```bash
sudo mkdir -p /opt
cd /opt
sudo git clone https://github.com/Xsenus/BibleMessengerBot.git bible-messenger-bot
cd bible-messenger-bot
```

Для работы без root используйте каталог, принадлежащий вашему пользователю. Команды Git в следующих руководствах предполагают, что у текущего пользователя есть права на рабочую копию. Не распаковывайте проект поверх каталогов других приложений.

## Автоматическая установка

Создайте бота у официального `@BotFather` и сохраните его токен приватно. Затем:

```bash
sudo bash install.sh
```

На новой установке токен запрашивается без вывода; создаются пароль БД, ключ admin и одноразовый код владельца. Если `.env` уже есть, установщик использует его. При существующем томе PostgreSQL нельзя создавать новый пароль вместо потерянного: восстановите исходный конфиг.

Этапы: проверка конфигурации → сборка образа → backup существующей БД → остановка приложения → готовность PostgreSQL → тесты в отдельной временной БД → миграции/импорт/аудит → запуск процессов → проверки готовности. Итоговые локальные отчёты сохраняются в `runtime-evidence/`. Ошибка завершает установку без обещания успешного запуска; после остановки процессов они могут остаться остановленными до устранения причины.

По умолчанию выбираются все допустимые редакции из трёх источников. Если нужен небольшой набор, сначала подготовьте `.env`, как описано ниже, и только затем запускайте установщик.

## Настройка перед первым запуском

```bash
umask 077
cp .env.example .env
chmod 600 .env
nano .env
```

В редакторе замените `BOT_TOKEN`, `OWNER_CLAIM_CODE`, `POSTGRES_PASSWORD`, `DATABASE_URL` и `ADMIN_API_KEY`. Пароль в `DATABASE_URL` должен совпадать с `POSTGRES_PASSWORD`; внутри Compose адрес БД — `postgres:5432`. Случайные hex-секреты можно получить командой `openssl rand -hex 32`, сохранив результат только в приватном конфиге.

Пример несекретных параметров ограниченного импорта:

```dotenv
BIBLE_PROFILE=all-open
BIBLE_SOURCES=biblenlp,getbible,helloao
IMPORT_LANGUAGES=ru,en
REQUIRED_LANGUAGES=rus,eng
DEFAULT_TIMEZONE=Europe/Moscow
IMPORT_ON_START=true
```

Фильтр языка допускает все разрешённые издания этих языков. Для ещё более узкого выбора используйте `IMPORT_EDITIONS=source:id,...` после просмотра каталога. Названия идентификаторов проверяются через `discover`, а не угадываются по названию перевода. Справочник параметров — [CONFIGURATION.md](CONFIGURATION.md).

## Ручной запуск Docker Compose

На системе с установленным Docker Engine/Compose и подготовленным `.env`:

```bash
docker compose config --quiet
docker compose build --pull bootstrap
docker compose up -d postgres
```

Дождитесь статуса `healthy` у PostgreSQL в `docker compose ps`. На существующей установке перед следующими командами сделайте backup и остановите `bot worker admin`.

```bash
docker compose run --rm --no-deps -e RUN_DB_TESTS=1 bootstrap python -m pytest -o addopts= -q
docker compose run --rm --no-deps bootstrap python -m app.bootstrap
docker compose run --rm --no-deps bootstrap python -m app.cli audit
```

Продолжайте только после успешных тестов, bootstrap и аудита:

```bash
docker compose up -d --no-deps bot worker admin
docker compose ps
curl --fail http://127.0.0.1:8080/ready
```

Если токена пока нет, допустимо подготовить БД, выполнить импорт и запустить только admin. Для этого оставьте `BOT_TOKEN` пустым, выполните ручные этапы до аудита и затем `docker compose up -d --no-deps admin`. Это не запущенный Telegram-бот: процессы `bot` и `worker` включаются после добавления действительного токена и проверки команд в Telegram.

## Доступ к административной странице

На своём компьютере откройте SSH-туннель (замените имя пользователя и хост):

```bash
ssh -N -L 8080:127.0.0.1:8080 operator@your-vps
```

Откройте `http://127.0.0.1:8080/admin`. Логин — `admin`, пароль — `ADMIN_API_KEY` из серверного `.env`. Если локальный порт занят, замените первый `8080`, например на `18080`, и откройте соответствующий адрес. Страница только для чтения; настройки меняются через Telegram.

## Приёмка

Проверьте `/start`, `/settings`, `/translations`, выбранное издание, `/next` и одну запланированную публикацию в собственном тестовом чате. Для канала отдельно проверьте права администратора, публикацию и паузу. Зафиксируйте точные результаты по [VALIDATION.md](VALIDATION.md). Успешные контейнеры и `/ready` сами по себе не подтверждают доставку через Telegram.

Для обновления используйте [OPERATIONS.md](OPERATIONS.md); для ошибок — [TROUBLESHOOTING.md](TROUBLESHOOTING.md). Не используйте `docker compose down -v`: команда удаляет данные проекта.
