# Установка и обновление 1.2.0

## Перед запуском

Это пакет исходников с автоматическим импортом, а не уже наполненная БД. Требуется интернет с VPS. Офлайн-проверки архива не доказывают успешность установки: см. `../RELEASE-AUDIT.md`.

Новая установка: распакуйте единый архив, перейдите в `BibleMessengerBot-1.2.0` и выполните `sudo bash install.sh`. Скрипт поддерживает Ubuntu/Debian, ставит Docker из официального APT-репозитория при отсутствии, запрашивает токен и создаёт секреты. Ничего не нужно отправлять разработчику. Токен вводится без отображения.

Скрипт выполняет реальную `docker compose config --quiet`, сборку и `pip check`, тесты с установленной aiogram и отдельной временной PostgreSQL-БД, bootstrap, полный аудит импортированной БД и проверки готовности служб. `set -Eeuo pipefail` останавливает установку при неуспехе. Вывод сохраняется в `runtime-evidence/`, кроме секретов. Тестовые данные явно помечены SYNTHETIC и удаляются вместе с временной тестовой БД: это не библейский текст.

Стандартный профиль — `extended`, максимум 2 редакции на язык. В `REQUIRED_LANGUAGES=rus,eng` задано обязательное наличие структурно полного 66-книжного ядра на русском и английском. Остальные отсутствующие языки выводятся в отчёте и не считаются загруженными. Полный профиль не гарантирует доступность всех 56 языков.

```bash
# Только для новой установки без существующего .env:
sudo BIBLE_PROFILE=core MAX_EDITIONS_PER_LANGUAGE=1 bash install.sh
```

Для существующей установки меняйте настройки в `.env`; установщик намеренно не перезаписывает их переменными оболочки. `BIBLE_PROFILE=none` — диагностический режим без импорта и без требования текстов; это НЕ готовый сервис чтения Библии. `all-open` может значительно увеличить время и дисковое пространство и тоже применяет проверку лицензий.

## Обновление с 1.1.0

1. Сохраните рабочий `.env` и резервную копию БД. Распакуйте новый архив отдельно, скопируйте `.env` из старого каталога (права 600).
2. На том же сервере выполните `sudo bash install.sh`. Фиксированное имя Compose-проекта сохраняет прежний том `bible-messenger-bot_postgres_data`. Старые службы останавливаются до миграции и импорта. Новые настройки берутся из кода по умолчанию, если их нет в старом `.env`.
3. Проверьте `runtime-evidence/database-audit.json`, `docker compose ps`, `/settings`, одну ручную публикацию и одну запланированную. Старые неоднозначные отправки переводятся в ручную проверку, а не слепо пересылаются.

Если `.env` потерян, а том уже существует, автоматическая генерация других паролей запрещена. Восстановите первоначальный файл. Обновление кода не является откатом БД: обратная миграция не реализована, для возврата нужен старый код и резервная копия до обновления.

## Административная страница

Порт привязан только к `127.0.0.1:8080` сервера (можно сменить `ADMIN_HOST_PORT`). На своём ПК:

```bash
ssh -L 8080:127.0.0.1:8080 user@your-vps
```

Откройте `http://127.0.0.1:8080/admin`, логин `admin`, пароль — `ADMIN_API_KEY` из `.env`. Страница диагностическая, только для чтения; настройки меняются через проверенные Telegram-команды, не через публичную админку. Если порт занят, установщик останавливается на готовности; смените порт в `.env` и повторите запуск.

## Неуспешный запуск

```bash
docker compose ps
bash diagnose.sh
```

Не удаляйте данные и не меняйте пароль БД наугад. Устраните причину (источник/сеть/токен/зависимость/SQL/права) и повторите установку. Сбой тестов или импорта — реальная ошибка, не успешная установка. Активный webhook от прежнего приложения не удаляется молча: эту конфигурацию нужно осознанно отключить перед long polling нового бота. Никогда не запускайте два poller одного токена на разных БД.
