# Готовые чтения и время молитвы (1.15.0)

Утренняя и вечерняя подписки хранят **время молитвы** в `send_time`. Чтение отправляется в начале того же часа, приглашение помолиться — в указанное время. Например, `09:13` означает чтение в `09:00`, молитву в `09:13`; `21:36` — чтение в `21:00`, молитву в `21:36`. Действующие значения по умолчанию: молитва **09:38 / 21:13**, чтение **09:00 / 21:00** в часовом поясе назначения. Используются IANA timezone и дни недели подписки; политика переходов летнего времени общая с основным планировщиком.

`/devotions` включает оба времени, `/devotions off` выключает. Индивидуальная настройка: `/subscribe morning 09:13 Asia/Novosibirsk` и `/subscribe evening 21:36 Asia/Novosibirsk`. `/time` сохраняет отдельные часы молитвы, меняя обычные подписки и timezone. `/status` показывает часы и подготовку. Стих дня сохраняет своё время и, если в ближайший час есть включённая молитва, тоже начинается с напоминания.

С версии 1.16.1 напоминание указывает время молитвы в скобках: «До совместной молитвы — 38 минут (09:38).» Время рассчитывается в часовом поясе выбранного чата; вечернее напоминание, например, показывает `(21:13)`. Отдельное приглашение помолиться не содержит технической строки часового пояса.

## Сборка перед отправкой

За сутки до следующей отправки `worker` фиксирует отрывок, адреса, издание и исходную карточку. `illustrator` заранее готовит иллюстрацию; `speaker` создаёт MP3 **для каждого предлагаемого языка и каждой страницы** этого отрывка. Доступность языков проверяется по реально импортированным текстам, включая латинский, древнегреческий или древнееврейский, когда они покрывают адрес. Это не машинный перевод. Кэш разделяется между пользователями, а при выборе языка готовая запись используется сразу. Исходные тексты, предпочтения чата и прогресс от переключения языка не меняются.

Для стиха дня, тематической, утренней и вечерней подписок первоначальная отправка разрешена только при готовности картинки **и всех** этих MP3. Напоминание помещается над библейским текстом; число минут рассчитывается непосредственно при отправке, поэтому задержка не оставляет устаревшее «через 38 минут». Озвучивается сам библейский отрывок. Кнопки языков, иллюстрация и аудиоплеер остаются в одной карточке. Ручные команды сохраняют быстрый ответ и последующее обновление медиа.

Подготовка переживает перезапуск в `scheduled_readings` и `reading_card_tracks`. Вызов аудиосинтеза разрешён для ещё не отправленной карточки только при активной, совпадающей по версии подписке. При изменении настроек старый пакет не публикуется. Изменившийся исходный стих блокирует старую картинку.

Если пакет не готов до молитвы, он помечается `skipped / media_deadline`, событие записывается в журнал, календарь переходит к следующему чтению. Для стиха дня и тематического чтения окно ожидания — 30 минут. Частичный пакет автоматически не отправляется. Приглашение на молитву имеет независимую очередь и не ждёт отсутствующие медиа чтения. Если чтение пропущено или подписка включена после начала часа, будущая молитва всё равно планируется.

## Приглашение и бесплатный ИИ

`composer` за 30 минут до молитвы готовит короткое приглашение «Давайте помолимся вместе» и молитву. Готовая иллюстрация чтения добавляется при отправке, если она есть; новый платный запрос ради приглашения не выполняется.

Опциональный профиль `prayers` запускает локальный Qwen3-0.6B Q8 на CPU через llama.cpp. Модель выбирает до трёх тем из фиксированного списка по заголовкам **UN News**. Из этих тем составляется короткая молитва из вычитанных прошений. Новости — данные, не инструкции; модель не пишет непроверенные факты, имена или числа. Такой текст помечается как подбор с помощью ИИ и содержит ссылки на источники. Он не обозначается библейским стихом или церковным богослужебным текстом.

Если русская лента ещё не обновилась, используется сегодняшняя английская лента ООН; прошения остаются на языке интерфейса. В RSS принимаются только публикации текущей даты в timezone подписки, без будущих дат и с HTTPS-ссылками на `news.un.org`. Сохраняются даты, ссылки, заголовки, версия генератора и готовый текст в `prayer_briefs`; один результат используется для одинаковых даты, timezone, утреннего/вечернего слота и языка интерфейса. Если сегодняшних материалов нет, RSS недоступен или локальная модель отказала, используется явно обозначенная общая молитва. Старые новости не выдаются за сегодняшние.

Платных API для молитвы нет; `PRAYER_AI_URL` допускает только локальные адреса. Модель скачивается из закреплённой ревизии с проверкой размера и SHA-256 ([манифест](../app/data/prayer-model.json)), без исполнения кода Hugging Face. Сервер модели доступен только внутренней сети Docker; порты на VPS не публикуются.

```bash
docker compose --profile prayers up -d prayer-ai composer
docker compose logs --tail=100 composer speaker illustrator worker
docker compose exec -T composer python -m app.healthcheck composer
```

Для автоматического включения профиля при последующих `docker compose up` можно задать `COMPOSE_PROFILES=prayers` в приватном `.env`. Для модели выделены отдельный том, максимум 1280 MiB RAM и один CPU; MP3 синтезируются отдельной службой. Модель около 610 MiB скачивается один раз. Расход CPU/диска VPS остаётся; оплаты за запросы нет. Без профиля бот работает с общей молитвой. [Модель](https://huggingface.co/Qwen/Qwen3-0.6B-GGUF), [сервер](https://github.com/ggml-org/llama.cpp/blob/master/docs/docker.md).

## Доставка, лимиты и восстановление

Ни чтение, ни молитва не отправляются раньше `scheduled_for`. Молитвы имеют приоритет среди готовых отправок. Общий SQL-ограничитель удерживает не более 20 отправок/сек, примерно одну/сек в личный чат и одну/3,2 сек в группы/каналы. [Лимиты Telegram](https://core.telegram.org/bots/faq#my-bot-is-hitting-limits-how-do-i-avoid-this). Ответ `429` учитывает `retry_after`; попытки ограничены. Оплаченная массовая рассылка не включается.

Перед сетью записывается checkpoint `sending`; после подтверждения Telegram сохраняются ID сообщения и прогресс. Неизвестный результат сети становится `uncertain` и требует `/resolve`, без автоматического дубля. После перезапуска редактирование повторяет только прежний ID, а новая отправка с неизвестным исходом не повторяется. Блокировка бота отключает чат.

Приглашение на молитву имеет срок отправки три минуты. Более поздняя попытка помечается `skipped / prayer_expired`: сообщение «давайте помолимся сейчас» не приходит через несколько часов. Назначенное время — начало отправки: сеть, ограничитель Telegram и `429` могут дать задержку; абсолютная доставка в конкретную секунду не гарантируется.

Миграция 016 добавляет таблицы и переносит только безопасные будущие утренние/вечерние чтения к началу часа. Подписки с незавершённой или неопределённой отправкой, оплаченные попытки, содержимое Библии, донаты и отправленная история сохраняются. При обслуживании останавливайте `bot worker admin illustrator speaker composer`, а сервер ИИ можно оставить работающим. После миграции проверяйте `/ready`, health всех служб, `scheduled_readings`, `reading_card_tracks`, `prayer_occurrences` и внутренний бюджет изображений.
