# Слежение за видеоканалами

Бот периодически проверяет каналы YouTube, RuTube и ВКонтакте и, если включена рассылка, отправляет ссылки на новые видео.

## Настройка

Бот: `/video` (список), `/video add youtube UC… [notify]`, `/video add rutube 12345`, `/video add vk club123`,
`/video on|off|notify|silent|del ID`, либо `/admin` → «Видео», либо веб-панель (интервал, шаблон, аудитория).

| Платформа | Что указать | Источник данных |
|---|---|---|
| YouTube | ID канала `UC…` (или ссылка с ним) | RSS `youtube.com/feeds/videos.xml?channel_id=` |
| RuTube | числовой ID автора или ссылка на канал | `rutube.ru/api/video/person/ID/` |
| ВКонтакте | `-123`, `club123` или номер владельца | `video.get` (нужен `VK_SERVICE_TOKEN`) |

## Правила

- **Первый опрос только запоминает** вышедшие видео — задним числом ничего не рассылается.
- Каждое видео записывается один раз (`UNIQUE(feed_id, external_id)`); рассылка идемпотентна (`video:<id>`).
- За один опрос рассылается не более 3 самых новых видео, остальные помечаются пропущенными.
- Шаблон сообщения: `{title}`, `{url}`, `{channel}`; по умолчанию «🎬 Новое видео: …».
- Сбой сети или формата не останавливает службу: интервал опроса растёт (до 6 часов), причина в поле `last_error`,
  метрика `bible_video_feeds_failing` и оповещение. Интервал по умолчанию — 30 минут (5…1440).
- Опрос выполняет служба `composer`; XML с DOCTYPE/ENTITY отвергается.
- Сбой постановки уведомления оставляет видео в `new`: следующий опрос добавляет недостающие задания,
  даже если видео уже исчезло из окна RSS. После частичной ошибки следующий опрос назначается через минуту.
  Одно видео допускает пять попыток; после устранения ошибки `/video retry ID` сбрасывает попытки ожидающих
  видео этого канала. Успешные уведомления и уже созданные задания при этом не дублируются.

Таблицы `video_feeds`, `video_items` (миграции 031, 039).
