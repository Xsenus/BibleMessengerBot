# Архитектура 1.3.0

Стек: Python, aiogram, PostgreSQL, отдельный worker, FastAPI и Docker Compose. Redis/нейросеть/платный API не требуются. Bootstrap — одноразовая служба подготовки; bot получает Telegram updates, worker планирует и публикует, admin предоставляет read-only административное представление.

Путь наполнения: обнаружение каталога → проверка прав конкретного издания → ограниченный HTTPS-downloader → исходный кэш с SHA-256 → строгий адаптер формата → аудит структуры → одна транзакция PostgreSQL на издание → проверка фактически записанного содержимого → provenance/отчёт.

`app/catalog/multisource/`: types/config, transport, licenses, sources, parsers, store, runner, cli. Старый entrypoint `run_import` делегирует новому runner; низкоуровневая вставка использует существующий импортёр, индексы и прикладную БД. Runtime берёт shared advisory maintenance lock; импорт и миграции требуют exclusive lock. Кэш дополнительно защищён process lock, БД — corpus lock. Массовой транзакции на весь мировой корпус нет: завершённые издания сохраняются при ошибке следующего.

Содержание и пользовательское состояние разделены. Языки/редакции/стихи — справочники и корпус. telegram_chats содержит настройки назначения; subscriptions — расписание; delivery_log и reading_progress — доставка/чтение. Source aliases не переименовывают выбранные пользователем ID. Новая миграция аддитивна, прежние SQL имеют те же контрольные суммы.

Нумерация — часть идентичности содержания. BibleNLP Original и native namespaces не считаются эквивалентными. Тематические ссылки без проверенной карты запрещены для native. Поиск/последовательность/случайный выбор используют индексы конкретного издания. Имена книг могут быть собственными для перевода.

Безопасность доставки из 1.2.0 сохранена: подтверждаются части, прогресс продвигается после подтверждённого отрывка, неоднозначный результат Telegram не повторяется автоматически. Это не exactly-once Telegram; оператор разбирает uncertain. Исходные ограничения и отсутствие live-приёмки: LIMITATIONS.md.
