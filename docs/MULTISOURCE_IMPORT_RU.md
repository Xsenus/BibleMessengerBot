# Автоматическое наполнение PostgreSQL — 1.3.0

## Результат работы

Скрипт добавляет проверенные издания прямо в БД BibleMessengerBot, а не создаёт несовместимый SQLite-файл. Сохраняет язык, редакцию, источник, книги, главы, стихи/диапазоны, лицензионные сведения, исходные и содержательные контрольные суммы. В меню бота появляются только активные импортированные издания с успешным структурным аудитом.

Архив проекта не содержит полного корпуса. Количество реально полученных языков, изданий и стихов вычисляется при запуске и записывается в отчёт. Нельзя заранее гарантировать доступность каждого внешнего файла или всех мировых переводов.

## Ресурсы и независимость

| Адаптер | Каталог/формат | Поведение |
|---|---|---|
| `biblenlp` | BibleNLP/eBible: CSV, TSV лицензий, VPL + общий vref | Все файлы одного запуска привязаны к одному Git commit |
| `getbible` | getBible/v2: translations.json, целое издание JSON, books.json | Используется лицензия конкретной редакции из каталога |
| `helloao` | HelloAO: available_translations.json, complete.simple.json, books.json | Лицензия подтверждается для конкретного eBible-ID либо специальным первичным объявлением BSB |

HelloAO и BibleNLP могут содержать материалы одного первоначального издателя: это разные ресурсы доставки, а не обещание трёх независимых переводов каждого текста. При отказе одного ресурса обрабатываются остальные; существующее издание не заменяется похожим с другого сайта. Отсутствующие стихи никогда не дописываются из другой редакции. HelloAO может проверять лицензию напрямую на eBible и не требует доступности GitHub для этого пути.

Для BibleNLP `BIBLENLP_REVISION=latest` разрешает ветку по умолчанию в неизменяемый SHA на начало запуска. При недоступности разрешения используется известная закреплённая ревизия с предупреждением/частичным статусом. Это явно не обещание актуального latest при ошибке сети. Можно вручную закрепить 40-символьный SHA. `--refresh` обновляет сохранённые файлы, но не меняет явно заданный commit.

## Новая установка

```bash
sudo bash install.sh
```

Новый `.env`: `BIBLE_PROFILE=all-open`, `BIBLE_SOURCES=biblenlp,getbible,helloao`. На существующем сервере `.env` сохраняется целиком: старый профиль автоматически не переписывается. Для последующего импорта без старого ограничения используйте `fill_database.sh`.

## Существующая установка: безопасное обновление

Положите полный проект 1.3.0 на тот же хост. Перенесите **старый** `.env`, а не `.env.example`. Compose-проект и имена постоянных томов прежние. Не удаляйте тома; внешний перенос БД на другой сервер требует отдельного восстановления backup.

```bash
sudo install -m 600 /actual/old/project/.env .env
sudo bash fill_database.sh
```

Порядок действий:

1. Проверить конфигурацию и собрать обновлённый образ bootstrap.
2. Скачать каталоги/лицензии/тексты, проверить кэш и структуру. Бот продолжает работать.
3. Дождаться PostgreSQL и сделать резервную копию `backups/*.dump`.
4. Запомнить и остановить работающие bot/worker/admin, получить блокировку обслуживания.
5. Применить новые миграции и импортировать подготовленные издания транзакционно.
6. Проверить реальные строки, индексы и контрольные суммы БД. Возобновить только службы, работавшие перед обслуживанием, и только после успешной проверки.

Пока выполняется фаза записи, публикации приостановлены. При сбое скачивания до обслуживания службы не останавливаются. При частичном импорте уже завершённые издания остаются, незавершённая транзакция откатывается. При плохом аудите службы остаются остановленными; исследуйте отчёт, не запускайте их принудительно.

## Команды

```bash
# Всё, что разрешено политикой и поддерживается форматом, без лимита языков/редакций:
sudo bash fill_database.sh

# Только инвентаризация и проверка лицензий; в БД ничего не пишется:
sudo bash fill_database.sh discover

# Только скачивание и разбор, без изменения БД:
sudo bash fill_database.sh download

# Ограничение языков (все разрешённые редакции выбранных языков):
sudo bash fill_database.sh --languages ru,en,es,fr,de,uk

# Набор ресурсов:
sudo bash fill_database.sh --sources biblenlp,helloao

# Точные издания — сначала смотрите реальные ID в discover:
sudo bash fill_database.sh --editions biblenlp:russyn,helloao:BSB

# Перекачать даже завершённые файлы, сохранив защиту от замены текста:
sudo bash fill_database.sh --refresh

# Сводка/полный последний отчёт:
sudo bash fill_database.sh status
sudo bash fill_database.sh status --full-report

# Справка без Docker и .env:
bash fill_database.sh --help
```

Фильтры языка/издания пересекаются. `--profile core` и `extended` ограничивают список кодов; `--max-editions 2` действует на успешные издания одного языка **в каждом ресурсе**, только для этих профилей. `all-open` игнорирует лимит редакций. `none` не загружает тексты. Полный перечень результатов инвентаризации хранится в receipt, даже когда stdout показывает сводку.

Двухбуквенные языковые фильтры понимают распространённые варианты ISO; хранящиеся языки сохраняют код источника. Макроязык, диалект и древний язык не объединяются в одну запись БД. Для однозначного выбора используйте конкретный код и source:id из отчёта или меню Telegram.

## Отчёты и коды завершения

`SOURCE_CACHE_DIR/reports/latest.json` — последний полный отчёт; рядом сохраняются отдельные отчёты запусков. В Docker это каталог `/app/cache/reports` в томе `source_cache`. `fill_database.sh` дополнительно сохраняет конфигурацию без секретов, stdout, stderr, аудит БД и полный результат импорта в `runtime-evidence/corpus-...-*`.

В отчёте: ресурсы и их ошибки, ревизия, выбранные и отклонённые кандидаты, причины пропуска, физические книги/главы/стихи, полнота, язык, лицензия, SHA-256, результат записи, фактические языки и отсутствующие запрошенные языки. `download` подтверждает подготовку файлов, а не наличие строк в PostgreSQL: проверяйте `database_written` и название команды.

Коды: **0** — успешное выполнение/инвентаризация/пропуск по none; **2** — частичный результат, включая ошибки источников и удержанные обновления; **1** — отказ; **130** — прерывание CLI. Штатно отклонённые лицензии не равны сбою сети. Скрипт не превращает частичный импорт в успешный только из-за восстановления служб.

## Возобновление и кэш

Повторите ту же команду после обрыва. Завершённые файлы перечитываются только после проверки SHA-256. Докачка использует HTTP Range с ETag/Last-Modified, проверяет ответ 206 и Content-Range. При игнорировании Range, ответе 416 или смене версии файл скачивается заново: несовместимые фрагменты не склеиваются. Каталоги обычно перечитываются при запуске; после фазы download импорт использует согласованный кэш.

Повреждённый завершённый кэш загружается заново. Если разбор сохранённого файла противоречит новому каталогу, выполняется одна свежая загрузка перед отказом. Проверки не восстанавливают потерянный текст догадками. Не удаляйте и не редактируйте кэш во время работы; блокировка предотвращает конкурирующие задания в одном кэше, отдельная блокировка защищает БД.

## Настройки .env

| Переменная | По умолчанию | Значение |
|---|---:|---|
| BIBLE_SOURCES | biblenlp,getbible,helloao | Ресурсы и порядок |
| BIBLE_PROFILE | all-open | Все разрешённые и поддержанные издания |
| BIBLENLP_REVISION | latest | Разрешение commit или явный 40-символьный SHA |
| IMPORT_LANGUAGES | пусто | Дополнительный фильтр ISO через запятую |
| IMPORT_EDITIONS | пусто | Фильтр source:id через запятую |
| MAX_EDITIONS_PER_LANGUAGE | 2 | Только core/extended, отдельно в каждом ресурсе |
| IMPORT_RETRIES | 5 | Попытки одного сетевого запроса |
| IMPORT_REQUESTS_PER_SECOND | 2 | Ограничение запросов к одному хосту |
| DOWNLOAD_TIMEOUT_SECONDS | 180 | Таймаут сетевой операции |
| IMPORT_MIN_FREE_MB | 1024 | Минимальный резерв на файловой системе кэша |
| IMPORT_MAX_CACHE_MB | 30720 | Ограничение объёма кэша |
| IMPORT_MAX_FILE_MB | 128 | Максимум одного скачиваемого файла |
| REQUIRED_LANGUAGES | rus,eng | Языки полного структурного ядра для новой установки |

Лимиты используют множители 1024. **30 GiB — ограничение кэша, не оценка размера всей установки.** PostgreSQL, индексы, Docker-образы, логи и backups требуют дополнительного диска. При достижении бюджета скрипт останавливается с отчётом; после освобождения места или изменения лимитов можно продолжить. Общий размер корпуса и требования RAM не измерены на live-данных. Для начала можно ограничить языки; масштабирование оценивать по фактическому использованию сервера.

## Защита существующих изданий

Первый импорт создаёт издание. Повторный импорт сверяет фактический текст БД и хеш подготовленного содержания, не сбрасывает чтение и не включает намеренно отключённое издание. Изменившийся файл с неизменным текстом может обновить сведения источника без изменения стихов.

При изменении самого текста результат `held`/частичный: старая редакция сохранена. `--replace-existing` допускает замену лишь после явного решения оператора и только когда издание не связано с подписками, прогрессом, выбранными настройками, историей доставки или другими зеркалами. Это не флаг для массового обновления текста действующих подписчиков.

Точные дубликаты могут объединяться по совпавшему содержанию, языку, пространству нумерации и совместимой атрибуции. Идентификаторы источников сохраняются в `translation_sources`. Для зеркального alias в меню/публикации остаётся основная запись с её названием и лицензией; альтернативные сведения доступны в provenance. Похожие названия или одинаковое число стихов не являются основанием объединения.

## Полнота, нумерация, ограничения формата

Проверяются уникальные координаты, непустой текст, диапазоны, главы, заявленные числа источника, фактические строки и книги. Определяется структурное 66-книжное ядро, NT/OT или частичный корпус. Пороговая проверка плотности и глав не доказывает точность каждого слова. Не предполагается, что у всех переводов обязано быть одинаковое число стихов.

BibleNLP использует нормализованный vref; native-источники сохраняют их номера. Тематические подборки прежней версии работают только на BibleNLP: для native нумерации нужны проверенные карты, иначе режим запрещён. При переключении на native старые тематические подписки останавливаются. Последовательное чтение и стих дня доступны независимо от этой карты.

Адаптер getBible поддерживает подтверждённое соответствие номеров книг 1–66. Издание с непроверенным номером книги выше 66 отклоняется целиком, а не молча обрезается. Другие адаптеры сохраняют поддержанные дополнительные USFM-коды. Отсутствующий complete.simple.json в HelloAO — ошибка издания, а не переход на тысячи непроверенных пословных запросов. Сноски/заголовки остаются в исходном JSON-кэше; в таблице verses и публикациях хранится только текст стихов.

## Лицензии

Автоматически допускаются распознанные Public Domain, CC0, CC BY и CC BY-SA при непротиворечивых сведениях. NC, ND, запреты распространения/скачивания, неизвестные и конфликтующие условия пропускаются. Лицензия программного репозитория не применяется автоматически к текстам Библии. Слишком неоднозначная декларация может потребовать ручной проверки даже при фактическом разрешении правообладателя. Нет флага обхода этой политики в поставке.

## Python CLI без работающего бота

Из корня проекта в окружении с зависимостями:

```bash
python -m app.catalog.multisource.cli discover --cache-dir ./cache
python -m app.catalog.multisource.cli download --cache-dir ./cache --languages ru,en
python -m app.catalog.multisource.cli status --cache-dir ./cache --full-report
```

Для этих команд не нужны токен бота и PostgreSQL. Для `import` нужен `DATABASE_URL`, asyncpg и право выполнить миграции; runtime должен быть остановлен. Локальный Python CLI читает переменные окружения, **не загружает .env автоматически**. На VPS предпочтителен Docker-скрипт, который передаёт env_file и делает backup/проверки. Не публикуйте секреты DSN в командах или журналах.

## Проверка на сервере

После завершения изучите отчёт, выполните `docker compose ps`, проверьте `/settings` и тестовую публикацию в двух разных чатах. Сравните несколько стихов/диапазонов с первоисточниками и проверьте расписание. Полный live-импорт, Docker и Telegram в среде подготовки не выполнены; локальные сетевые ответы синтетические. Отчёт сборки: `RELEASE-AUDIT.md`.
