# Безопасность реализации

Политика сообщения об уязвимостях — [SECURITY.md в корне](../SECURITY.md).

## Секреты и доступ

`.env` должен находиться вне Git и Docker build context; установщик создаёт его с правами `600`. Telegram-токен, ключ admin, пароль БД и одноразовый код владельца не являются частью исходников. После успешного `/claim` повторное получение роли по тому же коду не допускается; роль владельца не обходит авторизацию Telegram.

Каждая команда или callback управления группой/каналом повторно проверяет реального пользователя и права бота. Callback содержит назначение, но его содержимое не считается доказательством полномочий. Удалённое управление допускается из личного чата; произвольный чужой положительный user-ID не является допустимой целью.

SQL-значения передаются параметрами. Текст и метаданные экранируются перед HTML-выводом; части Telegram учитывают его ограничения длины. Загрузчик ограничивает размер, число попыток, скорость и кэш, а идентификаторы источника проходят валидацию. Хеш подтверждает согласованность сохранённых байтов, но не является цифровой подписью правообладателя.

## Сетевая модель

PostgreSQL не публикует порт наружу. Admin привязан к `127.0.0.1` на хосте и имеет только операции чтения. `/admin` использует HTTP Basic (`admin` / `ADMIN_API_KEY`), `/api/stats` — заголовок `X-Admin-Key`; пустой или короткий ключ не проходит. `/health` и `/ready` не требуют ключа и доступны на том же локальном порту.

Для доступа используйте SSH-туннель. Публикация HTTP Basic прямо в интернет требует отдельной защищённой конфигурации и не входит в штатный сценарий. Контейнер приложения работает не от root, сбрасывает capabilities и использует `no-new-privileges`. Root/администратор Docker на VPS всё равно имеет доступ к секретам и данным.

Роль PostgreSQL штатного контейнера имеет расширенные права, в том числе создание тестовых БД. Раздельные роли миграции и runtime с минимальными привилегиями в текущем Compose не настроены. Runtime/maintenance locks защищают одну БД; одинаковый токен на другой БД ими не охватывается.

## Данные и журналы

БД содержит Telegram-ID, известные профили/названия чатов, выбранные настройки, прогресс, подписки, очередь/историю доставки и действия оператора. Backup содержит эти же данные. Административный интерфейс ограничивает объём вывода и не выводит токен или текст очереди, но ID назначений остаются частными операционными данными.

Не включайте сырые журналы, дампы и `runtime-evidence` в публичную публикацию без просмотра. Известные секреты маскируются приложением, но этот фильтр не заменяет проверку содержимого. Автоматического полного удаления аккаунта и универсальной политики сроков хранения нет; `/unsubscribe` прекращает рассылку.

Сохраняйте резервные копии независимо от VPS, ограничьте доступ и периодически проверяйте фактическое восстановление. Инструкция — [OPERATIONS.md](OPERATIONS.md). Полный независимый аудит безопасности и обещанный SLA не заявляются.
