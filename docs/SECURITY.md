# Безопасность

`.env` создаётся с правами600, исключён из Git/Docker build/archive. Токен и ключи не встроены в код; одноразовый код владельца с постоянным временем сравнения не переиспользуется после claim. Первая регистрация владельца не разрешает писать произвольным пользователям или обходить права Telegram.

Для каждого группового/канального действия заново проверяются права реального Telegram-пользователя и право бота публиковать. Callback включает назначение и тоже проверяется; нельзя доверять скрытой кнопке вместо серверной авторизации. Посторонние личные ID не являются допустимой целью рассылки. Групповые анонимные отправители управляют из личного чата.

SQL-значения параметризованы; динамические имена таблиц — только фиксированные внутренние константы. Текст Библии/метаданные HTML-экранируются, а длина Telegram ограничивается UTF16. Загрузка ограничена размером, ревизия фиксирована, кеш проверяется хешами. Кеш не является цифровой подписью правообладателя и не защищает от злонамеренного изменения кода/хешей самим администратором сервера.

PostgreSQL не публикует порт наружу. Админка доступна только через loopback/SSH, ключ минимум24 символа, read-only. Не переносите127.0.0.1 на0.0.0.0 без отдельной защиты/HTTPS. Контейнер приложения не root, cap_drop ALL, no-new-privileges. Сам пользователь PostgreSQL штатного контейнера имеет полномочия создания БД для интеграционных тестов; это не раздельные least-privilege роли. При повышенных требованиях разграничьте миграционную и runtime роли отдельной доработкой.

Изменение корпуса/схемы запрещено во время работы служб через shared/exclusive maintenance lock. Singleton-процессы защищены в пределах БД, но не от запуска того же токена на другой БД. Администратор VPS имеет доступ ко всем секретам и пользовательским данным.

Редакционный текст, поиск пользователя, идентификаторы чатов и история хранятся локально. Автоматическое полное удаление всех персональных следов и политика сроков хранения не реализованы. `/unsubscribe` отменяет рассылку, но не является стиранием аккаунта/журналов. Настройте собственную политику хранения и ограничение доступа к backups. Полный аудит информационной безопасности/CVE/нагрузки не проведён.
