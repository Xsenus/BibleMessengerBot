# Эксплуатация

Все команды выполняются из каталога проекта на нужном Docker-хосте. При нестандартном имени Compose-проекта используйте то же `COMPOSE_PROJECT_NAME`, что при установке. Нельзя выполнять обслуживание второй копией с другим конфигом поверх действующего тома.

## Состояние и журналы

```bash
docker compose ps
docker compose logs --tail=100 bot worker admin
bash diagnose.sh
docker compose run --rm --no-deps bootstrap python -m app.cli stats
docker compose run --rm --no-deps bootstrap python -m app.cli audit
```

`/health` проверяет живость admin, `/ready` — доступность БД и метаданные необходимого корпуса. Полный `app.cli audit` дополнительно проверяет физические строки, индексы и хеши. Bot/worker проверяются по heartbeat в БД: это не сквозной тест Telegram. Приложение скрывает известные секреты в логах, но перед публикацией диагностические файлы следует просмотреть и удалить частные идентификаторы. Не публикуйте `.env`, дампы и пользовательские сообщения.

Штатные службы имеют `restart: unless-stopped`. После перезагрузки Docker восстанавливает работавшие службы; вручную остановленный контейнер остаётся остановленным. Статус `unhealthy` не запускает Docker-перезапуск сам по себе: причину нужно проверить. `bootstrap` — одноразовая задача, её успешный `Exited (0)` нормален.

## Резервное копирование

```bash
sudo bash backup.sh
```

Скрипт делает согласованный `pg_dump` в custom-format, сначала пишет `.part`, затем завершает файл и вычисляет SHA-256. Итог — `backups/biblebot-<UTC-время>-<PID>.dump` и соответствующий `.sha256`. Новые файлы создаются с ограниченными правами. Dump содержит не только стихи, но и Telegram-ID, настройки, прогресс, историю и очередь сообщений.

Скопируйте dump, его checksum и действующий `.env` в независимое защищённое хранилище. Сам скрипт не выполняет шифрование, отправку вне сервера, расписание или удаление старых копий. Частоту и срок хранения задаёт оператор; резервная копия на том же диске не защищает от потери VPS. Сохраните commit кода (`git rev-parse HEAD`) и сведения об установленных зависимостях. Кэш можно скачать повторно, однако его сохранение вместе с отчётами полезно для воспроизведения происхождения конкретного текста.

Проверка checksum из каталога проекта:

```bash
sha256sum -c backups/YOUR_BACKUP.dump.sha256
```

Чтобы подтвердить восстанавливаемость, выполните:

```bash
sudo bash verify_backup.sh backups/YOUR_BACKUP.dump
```

Скрипт создаёт уникальную временную БД, восстанавливает в неё dump, проверяет корпус и содержательные хеши, затем удаляет временную БД. Действующая БД не заменяется. Требуются дополнительное место для копии и роль с правом создания БД. Читаемый список `pg_restore --list` сам по себе не заменяет эту проверку.

Для ежедневного backup предусмотрены systemd units в `deploy/`. Они рассчитаны на каталог `/opt/bible-messenger-bot`; при другом пути сначала исправьте `WorkingDirectory` и `ExecStart` в копии service-файла.

```bash
sudo install -m 644 deploy/bible-messenger-backup.service /etc/systemd/system/
sudo install -m 644 deploy/bible-messenger-backup.timer /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now bible-messenger-backup.timer
systemctl list-timers bible-messenger-backup.timer
```

Таймер с `Persistent=true` выполняет ежедневный запуск с небольшой случайной задержкой и догоняет пропущенный запуск после простоя. Результаты: `journalctl -u bible-messenger-backup.service`. Таймер не удаляет старые dump и не отправляет их вне сервера — следите за местом и независимыми копиями.

## Восстановление

Команда заменяет данные текущего проекта. Проверьте хост, каталог и имя dump, затем:

```bash
sudo bash restore.sh backups/YOUR_BACKUP.dump --confirm-replace-data
```

Скрипт проверяет формат dump, делает backup текущей БД, останавливает приложение, восстанавливает данные в одной транзакции, применяет схему/статические данные и выполняет аудит. **По умолчанию службы остаются остановленными.** Восстановление старой БД не удаляет уже опубликованные сообщения Telegram: перед запуском worker нужно согласовать очередь и прогресс с реальными чатами.

После проверки состояния:

```bash
docker compose up -d --no-deps bot worker admin
docker compose ps
```

Флаг `--start-services` позволяет явно запросить запуск после успешного восстановления; используйте его только после оценки риска повторной доставки. При ошибке службы остаются остановленными. Не исправляйте ошибки удалением тома и не запускайте worker в обход аудита.

## Обновление кода

На действующей установке сохраните `.env`, commit и backup. Рабочая копия должна быть без неизвестных локальных изменений:

```bash
git status --short
git rev-parse HEAD
sudo bash backup.sh
git fetch origin
git log --oneline HEAD..origin/main
```

Просмотрите изменения и [CHANGELOG](../CHANGELOG.md). Для обновления текущей ветки `main` без локальных коммитов:

```bash
git pull --ff-only
sudo bash update.sh
```

`update.sh` требует существующий `.env` и использует установщик: он собирает новый образ, проверяет зависимости/БД, применяет миграции и запускает службы после проверок. Настройки импорта из `.env` сохраняются. Если повторная загрузка при каждом обновлении не нужна, используйте `IMPORT_ON_START=false` после успешного наполнения; аудит существующих данных всё равно выполняется.

При переходе между каталогами на том же Docker-хосте перенесите прежний `.env` с правами `600` и сохраните имя Compose-проекта. Перенос на другой сервер требует восстановления dump; копирования исходников недостаточно. Уже применённые SQL-файлы нельзя редактировать: приложение проверяет их хеши.

Откат кода не откатывает миграции автоматически. До возврата старого commit оцените совместимость схемы. При необходимости восстанавливайте предобновительный dump и согласуйте Telegram-историю до запуска рассылки.

## Добавление текстов

```bash
sudo bash fill_database.sh discover --languages ru,en
sudo bash fill_database.sh --languages ru,en
sudo bash fill_database.sh status --full-report
```

Скачивание происходит при работающем приложении. Перед записью выполняются backup и остановка процессов; каждое издание сохраняется своей транзакцией. Завершённые издания остаются при ошибке следующего. По окончании только ранее работавшие службы запускаются после успешного аудита целостности. Сценарий обслуживания проверяет БД с профилем `none`, поэтому отдельно контролируйте readiness штатного профиля и требуемые языки.

Код `2` — частичный результат. Изучите отчёт, причины `failed`/`held` и пропущенные языки. `--refresh` повторно получает исходные файлы, а изменившийся текст действующего издания всё равно защищён от автоматической замены. Подробнее — [MULTISOURCE_IMPORT_RU.md](MULTISOURCE_IMPORT_RU.md).

## Неопределённая доставка

`/status [target]` показывает задания. `uncertain` означает, что приложение не может доказать, получил ли Telegram спорную часть. Откройте чат, сравните опубликованный текст с заданием и выберите действие от администратора назначения:

```text
/resolve 123 sent @your_channel
/resolve 123 retry-duplicate-risk @your_channel
/resolve 123 cancel @your_channel
```

`sent` подтверждает спорную часть и разрешает продолжить остаток; `retry-duplicate-risk` повторяет её с риском дубля; `cancel` отменяет остаток. Решение записывается в `operator_events`. Команда также применима к остановленным заданиям `failed`. Не удаляйте `delivery_log` для «исправления» доставки.

`/pause` сохраняет подтверждённые части и прогресс. `/resume` продолжает разрешённые задания; спорные требуют явного решения. `/unsubscribe` прекращает выбранные публикации, но не удаляет аккаунт и журналы. Изменение языка/издания/прогресса при незавершённой спорной доставке может быть заблокировано, пока оператор не завершит или отменит задание.

## Диск и производительность

Проверяйте `df -h`, `docker stats --no-stream` и `docker system df`. Compose ограничивает память и CPU приложения; точные значения находятся в `docker-compose.yml`. При `OOMKilled` сопоставьте размер корпуса и лимиты; увеличивайте только ресурсы этого проекта после оценки запаса сервера. Не запускайте глобальную очистку Docker на сервере с другими приложениями. Бюджет кэша не контролирует размер PostgreSQL, логов и backups.
