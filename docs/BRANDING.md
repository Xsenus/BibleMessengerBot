# Оформление и навигация Telegram

Публичное имя бота — «Библия каждый день»; английская версия — `Bible Every Day`. Имя профиля не меняет Telegram-username или ссылку на бота. В приложении используются собственные изображения, короткое приветствие, меню команд и стандартные клавиатуры Telegram.

## Автоматическое оформление профиля

`app/bot/branding.py` задаёт имя, полное описание, краткое описание, 16 команд и аватар через Bot API. Русские тексты используются по умолчанию и для `ru`, английские — для `en`. Команды имеют переводы из 24 доступных UI-каталогов; краткие RU/EN-описания ориентированы на основные действия читателя. Кнопка меню открывает список команд. Дополнительные операции `/unsubscribe`, `/reset`, `/resolve`, `/claim` и тематические команды сохраняются в справке/документации, даже если не вынесены в основное меню.

Оформление применяется фоновым процессом после запуска `bot`; оно не задерживает polling. Для каждого успешно принятого компонента сохраняется SHA-256 в `app_settings`. Неизменённые данные повторно не отправляются. При временной ошибке обновление откладывается; цикл учитывает `RetryAfter` Telegram. Отсутствующая картинка не блокирует работу команд. Сохранённый хеш означает, что Telegram ранее принял значение; постоянной сверки ручных изменений профиля через BotFather с сервером нет.

В проекте нет отдельных переменных `.env` для текстов оформления. Для собственного оформления измените `PROFILE` / `COMMAND_DESCRIPTIONS` в `app/bot/branding.py` и файлы изображений, затем пересоберите образ и пересоздайте `bot`:

```bash
docker compose build bootstrap
docker compose up -d --no-deps --force-recreate bot
```

Изменённые компоненты применятся по новому хешу. Перед публикацией собственного профиля сверяйте описание с действительно установленными переводами. Стандартное описание упоминает Синодальный перевод и World English Bible, использованные в проверенном начальном корпусе.

Bot API поддерживает отдельные методы [имени](https://core.telegram.org/bots/api#setmyname), [описания](https://core.telegram.org/bots/api#setmydescription), [краткого описания](https://core.telegram.org/bots/api#setmyshortdescription) и [аватара](https://core.telegram.org/bots/api#setmyprofilephoto). Ограничения длины проверяются тестами профиля; username через этот модуль не меняется.

## Приветствие и кнопки

В личном чате `/start` показывает приветствие с выбранным изданием и основными действиями.

Приветствие отправляется одной фотографией `assets/brand/welcome.png` с подписью и клавиатурой. Telegram `file_id` сохраняется в `app_settings` с привязкой к ID бота и SHA-256 картинки, поэтому повторный `/start` использует уже загруженный файл. При замене изображения получается новый ключ кэша. Если картинка отсутствует или фото не удалось отправить, предусмотрено текстовое приветствие. `/menu`, обычные кнопки и групповые команды не присылают welcome-фото повторно.

Постоянная клавиатура состоит из трёх рядов по две кнопки:

| Кнопка | Команда |
|---|---|
| 📖 Читать дальше | `/next` |
| 🌅 Стих дня | `/today` |
| 🎲 Случайный стих | `/random` |
| 🔎 Поиск | `/search` с подсказкой синтаксиса |
| ⚙️ Настройки | `/settings` |
| ❔ Помощь | `/help` |

Нажатие известного текста кнопки проходит через тот же обработчик и авторизацию, что ручная команда. `/menu` возвращает навигацию. Выбор языка, издания и режима остаётся в inline-кнопках под сообщениями. В обычной переписке групп свободный текст не обрабатывается как команда; постоянная клавиатура предназначена для личного чата.

## Названия переводов и подписи

Пользовательские экраны показывают понятное название перевода, включая приветствие, настройки, выбор издания, статус и результат чтения. Например, технический ID `synodal` отображается как «Синодальный перевод». Для Public Domain/CC0 под стихом или главой остаётся короткое название издания; подробные сведения об источнике, лицензии и нумерации доступны в `/license` с понятными пояснениями.

Если лицензия требует атрибуции, обязательные сведения сохраняются вместе с публикацией. Исходный текст Библии, метаданные источника и идентификаторы в БД этим оформлением не изменяются. Подробности — [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md).

## Что определяет сам Telegram

Шрифты, масштаб интерфейса, тема, фон чата и размещение стандартных элементов зависят от клиента и настроек пользователя. В этом проекте нет отдельного Web App с произвольной HTML/CSS-разметкой. Приложение использует форматирование сообщений, эмодзи, собственные изображения и [стандартные клавиатуры Telegram](https://core.telegram.org/bots/api#replykeyboardmarkup). Точный вид следует проверять на телефоне и desktop-клиенте, включая светлую и тёмную темы.

Картинка описания, видимая до первого сообщения, — отдельный элемент профиля BotFather. Модуль оформления её не устанавливает, а изображение `/start` является сообщением в чате. Если нужна именно картинка описания, владелец настраивает её отдельно в BotFather; не следует считать отправленную welcome-картинку подтверждением изменения этого поля.

## Проверка изменения

После пересоздания bot проверьте профиль, меню команд, `/start`, русскую/английскую навигацию и кнопки. Ошибки фонового оформления видны в `docker compose logs --tail=100 bot` без вывода токена. Автоматические тесты проверяют длины текстов, применение по хешу, клавиатуру и обработку команд; реальный вид и успешная загрузка изображения требуют отдельного Telegram-теста. Текущий результат — [VALIDATION.md](VALIDATION.md).
