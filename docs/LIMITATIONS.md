# Подтверждённые границы 1.3.0

## Наполнение и источники

Полные реальные Библии и дамп PostgreSQL в ZIP **отсутствуют**. Новая реализация должна скачать их на VPS. Доступ к страницам источников/документации проверялся через web/коннектор; прямое скачивание файлов из среды исполнения не проходило DNS. Сетевые тесты используют синтетические данные, не настоящую Библию. Доступность всех каталогов, полных файлов и соответствие каждого их экземпляра контракту не подтверждены live-прогоном.

Поддержаны три адаптера, не «все сайты мира». all-open охватывает доступные поддержанные редакции, признанные разрешёнными. Коммерческие, NC/ND, неизвестные/конфликтующие лицензии не импортируются. Новые источники, произвольные USFM/OSIS и чужие SQL/SQLite-дампы не являются реализованными универсальными импортами.

getBible: непроверенные номера книг выше 66 отклоняют издание целиком. HelloAO: отсутствие полного simplified endpoint отмечается как ошибка; сноски и заголовки остаются в сыром кэше, не публикуются как стихи. BibleNLP: нормализованный Original vref, не исходная печатная нумерация. Неполные тексты не достраиваются из другого перевода.

## Полнота и язык

Флаги canonical_66_complete/nt_complete — структурные проверки набора книг, глав и плотности/индексов, а не доказательство каждого слова и стиха. Наличие 66-книжного ядра не означает полного православного состава. Независимая текстологическая/богословская сверка не проводилась. 24 UI-каталога не проходили независимой вычитки носителями; не все названия книг локализованы.

Тематические ссылки применимы только к BibleNLP. Для native-источников тематический режим запрещён; переключение на такое издание останавливает прежнюю тематическую подписку. Установленного церковного календаря, богослужебных чтений по конфессии и inline-mode нет. Стих дня — алгоритмический выбор, не календарное богослужебное чтение.

## Проверки и развёртывание

Локально выполнены Python/offline-тесты, компиляция, shell-синтаксис, JSON/YAML, проверки кэша и synthetic HTTP; shell-оркестрация тестировалась с fake Docker. Настоящие aiogram/PostgreSQL-интеграционные модули пропущены из-за недостающих компонентов. Docker image/Compose runtime, полный импорт, Telegram, backup/restore, нагрузочный soak и промышленная приёмка здесь не выполнены. Установщик содержит их часть для выполнения на целевом VPS, но это не состоявшийся результат.

Лимит кэша и минимум свободного места не являются общим лимитом расхода БД/backup. Нет измеренного SLA, точной оценки диска/RAM на весь корпус, полностью hash-locked dependency graph и запуска vulnerability audit/Ruff. Офлайн PASS не означает гарантии отсутствия ошибок.

Обновление скриптом требует сохранения .env на том же Docker-хосте. Если импорт/миграция/аудит падают, оператор должен проверить отчёт и backup. Повторный запуск не должен обходить ошибки или удалять тома. При смене текста используемые издания намеренно удерживаются, поэтому обновление не обещает автоматическую замену всей действующей библиотеки.

## Доставка

Telegram не даёт приложению универсальной exactly-once гарантии. Неопределённая отправка требует ручного решения с проверкой чата. Уже отправленные сообщения не откатываются транзакцией БД. Восстановление старого backup может рассинхронизировать историю с Telegram; необходима проверка оператора. Бот не пишет первым произвольным пользователям и работает только с разрешёнными назначениями.
