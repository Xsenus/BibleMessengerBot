# Политика безопасности

Исправления следует проверять на текущей ветке проекта. Отдельного обещанного срока поддержки исторических архивов и SLA реакции нет. Старые отчёты проверки не подтверждают безопасность нового commit.

## Сообщение об уязвимости

Не публикуйте в issue действующие секреты, данные чатов, дампы и инструкции с реальными целями атаки. Если в репозитории доступна функция GitHub **Security → Report a vulnerability**, используйте её для приватного сообщения. Если она недоступна, создайте issue только с просьбой о приватном канале связи, без подробностей эксплуатации и чувствительных данных.

Полезны: затронутый commit, условия воспроизведения, минимальный пример на синтетических данных, ожидаемое и фактическое поведение. Возможную утечку токена устраняют отзывом в BotFather и заменой `.env`; удаление секрета из текущего файла не отзывает опубликованный токен.

## Развёртывание

- Храните `.env` с правами `600`, отдельно от Git, журналов и публичных артефактов.
- PostgreSQL в штатном Compose не публикует порт; административный порт доступен только через `127.0.0.1`.
- Открывайте `/admin` через SSH-туннель. Имя пользователя — `admin`, пароль — `ADMIN_API_KEY` длиной не менее 24 символов.
- Резервные копии содержат Telegram-ID, настройки, прогресс и очередь сообщений. Храните независимую защищённую копию вместе с конфигурацией.
- Не запускайте один Telegram-токен одновременно в независимых установках; блокировки внутри одной БД не координируют разные серверы.

Подробности встроенных ограничений и модели данных — [docs/SECURITY.md](docs/SECURITY.md). Эта политика не заменяет проверку конкретного сервера, обновление системных пакетов и проверку прав доступа.
