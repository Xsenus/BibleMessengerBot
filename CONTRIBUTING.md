# Участие в разработке

Обсуждения и документация преимущественно на русском; issue и pull request на английском также подходят. Перед изменением прочитайте [архитектуру](docs/ARCHITECTURE.md), [ограничения](docs/LIMITATIONS.md) и [правила безопасности](SECURITY.md).

## Локальная среда

Нужен Python 3.12 или новее. Для воспроизведения контейнерного окружения используйте версию из `Dockerfile`. PostgreSQL и токен Telegram не нужны для основной части модульных тестов.

```bash
python -m venv .venv
# Linux/macOS:
source .venv/bin/activate
# PowerShell вместо предыдущей команды:
# .\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements-dev.txt -r requirements-test.txt
python -m pytest -o addopts= -q
python -m compileall -q app tests
```

Полный набор с PostgreSQL и ручная приёмка описаны в [VALIDATION.md](docs/VALIDATION.md). Пропущенные тесты (`skipped`) не считаются выполненными. Не используйте продукционные учётные данные для разработки; тестовая PostgreSQL-роль должна иметь право создавать отдельные временные БД.

## Изменения

1. Создайте отдельную ветку с понятным названием.
2. Ограничьте изменение одной задачей и объясните её в PR.
3. Добавьте содержательный регрессионный тест для исправления ошибки в данных, авторизации, доставке или импорте.
4. Обновите документацию при изменении команды, настройки или поведения.
5. Приведите команды проверки и фактический результат, включая пропуски и ограничения.

Не правьте уже применённые SQL-файлы: их SHA-256 записан в `schema_migrations`. Для изменения схемы добавьте следующую миграцию в `sql/migrations/` и проверьте повторное применение. Импорт должен сохранять пользовательские настройки, прогресс и действующие идентификаторы изданий.

Изменения доставки должны учитывать подтверждение каждой части, конкурирующие процессы, `uncertain`, паузу и перезапуск. Не добавляйте автоматический повтор неоднозначно отправленного сообщения. Для новых источников нужны реальные документированные форматы, отдельная проверка лицензии, ограничения загрузки, доказательства происхождения и синтетические тестовые данные, явно обозначенные как тестовые.

## Комментарии в коде

Каждая функция, метод и класс в `app/` и `scripts/` имеет docstring на русском языке: что делает, что принимает и возвращает, какие побочные эффекты и ограничения (блокировки, идемпотентность, безопасность). Новый код пишите так же; короткие однострочные docstring достаточны для простых функций.

## Проверки качества (выполняются в CI)

```bash
python -m pip install -r requirements-dev.txt
ruff check .                      # правила E/F/B/UP/SIM; стилевые отключены намеренно
mypy                              # строго для всех модулей, кроме списка в [[tool.mypy.overrides]]
python -m pytest -o addopts= -q --cov=app   # порог покрытия 75 %
pip-audit -r requirements.txt --disable-pip
```

Список `[[tool.mypy.overrides]]` в `pyproject.toml` — «храповик»: исправив модуль, удалите его из списка; новый код проверяется полностью.
Не смешивайте массовое форматирование старого кода с функциональным исправлением. Dependabot предлагает обновления pip/Actions/Docker; образ собирается и сканируется Trivy,
по тегу `v*` публикуется в GHCR. Тесты с `RUN_DB_TESTS=1` требуют PostgreSQL ([VALIDATION](docs/VALIDATION.md)); OCR-проверки картинок — пакета `tesseract-ocr`.

## Что прикладывать к issue

Укажите версию/commit, ОС, версии Python/Docker Compose, команду, ожидаемый результат и очищенный фрагмент ошибки. Для импорта приложите источник, `source:id`, status и причину отказа из отчёта. Для Telegram — вид чата и статус задания, без идентификаторов пользователей и текста личных сообщений.

Не прикладывайте `.env`, токены, пароли, дампы, исходные пользовательские журналы и закрытые переводы. Уязвимости сообщайте по [SECURITY.md](SECURITY.md). Изменения кода распространяются по лицензии проекта; добавляемые сторонние материалы должны иметь совместимые права и атрибуцию.

Офлайн-отчёт можно получить командой `python scripts/release_audit.py`: он сохраняется в `runtime-evidence/offline/` и не перезаписывает опубликованный `RELEASE-AUDIT.*`.
